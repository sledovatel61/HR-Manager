## Шаг 1. Убрать след прошлой установки

Мастер помнит прежний каталог в записи деинсталлятора и без `/DIR` пойдёт туда
снова. Убираем запись целиком (побочный эффект: HR Manager пропадёт из
«Установка и удаление программ» — на приёмке это нормально).

```powershell
$keys = @(
  'HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*',
  'HKCU:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*'
)
Get-ItemProperty $keys -ErrorAction SilentlyContinue |
  Where-Object DisplayName -like '*HR Manager*' |
  ForEach-Object { Write-Host "Убираю: $($_.DisplayName)"; Remove-Item $_.PSPath -Recurse -Force }
```

## Шаг 2. Запустить мастер и запомнить код возврата

`/DIR` обязателен. Каталог должен существовать или создаётся мастером.

```powershell
$exe = 'C:\hrm-accept\ci625\Setup.exe'
$p = Start-Process -FilePath $exe -ArgumentList '/DIR=C:\hrm-accept\ci625\install' -Wait -PassThru
"КОД ВОЗВРАТА: $($p.ExitCode)"
```

Каталог для логов приёмки: `C:\hrm-accept\ci625-20261021\`.

## Шаг 3. Что записать — ровно пять пунктов

1. **Код возврата.** `0` = успех, `10` = движок не подтвердил готовность.
   Это главный пункт: он и есть предмет сегодняшней проверки.
2. **Открылось ли окно регистрации само**, без ручного открытия браузера.
3. **Фамилия.** Ввести **кириллицей** (например `Иванов`), дойти до профиля и
   записать, что там показано. Это проверка починки `54d68fc`: раньше фамилия
   приезжала кракозябрами и исправить её было нечем. Если показано `Иванов` —
   починка подтверждена. Если `Owner` или кракозябры — нет.
4. **Содержимое** `%LOCALAPPDATA%\HRManager\setup-run.json` (если файл есть —
   при успехе он удаляется движком, и его отсутствие **не** считается провалом).
5. **Содержимое** `installer-result.json` из каталога состояния.

Плюс скриншот профиля с фамилией.

## Шаг 4. Чего не делать

Не переустанавливать повторно без нужды, не `docker compose down -v`, не удалять
тома `hr-manager-pilot_pilot_pgdata` и `hr-manager-pilot_pilot_backups`, не
трогать стек на 8080.
