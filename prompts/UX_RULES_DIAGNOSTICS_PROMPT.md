# Задача: понятные «Мои правила» и перенос диагностики в администрирование

Репозиторий: https://github.com/sledovatel61/HR-Manager
База: свежий `main`. Ветка `arena/<id>-ux-rules-diag`, один PR в `main`.
Только frontend (и, если нужно, read-only endpoint для preview). Установщик,
`infra/windows/` и функции графика выхода не трогать — их делают другие агенты.

Пользователь — HR-менеджер без технических знаний. Задача небольшая, это
доводка удобства, а не новая функциональность.

## 1. «Мои правила» (`frontend/src/features/documents/MyRulesPage.tsx`)
- Переименовать поля человеческим языком: «Триггер» → «Когда это происходит»,
  «Действие» → «Что сделать», «Канал» → «Куда отправить». В таблице списка
  правил — те же названия.
- Живой блок «Что произойдёт» рядом с формой. Он пересчитывается при каждом
  изменении полей и одной-двумя фразами говорит, когда, для каких кандидатов,
  что будет сделано, каким каналом и с каким текстом (первые ~200 символов).
  Учитывает тихие часы и рабочие дни («если это случится ночью — отправим в
  9:00»), а также то, что правило срабатывает только для кандидатов, к которым
  у автора есть доступ. Если форма заполнена не до конца, блок пишет, чего не
  хватает.
- Preview строится на клиенте по данным формы и настройкам профиля. Если нужен
  сервер — только read-only endpoint, который **не создаёт** outbox-сообщений и
  задач (на это нужен тест).
- Свернутый блок «Как это работает» (3–5 пунктов): правило срабатывает на
  событие; правка/выключение отменяет ожидающие отправки; тихие часы;
  история срабатываний.

## 2. Диагностика в администрировании
- Убрать отдельный пункт меню «Готовность пилота»
  (`frontend/src/app-shell/Workspace.tsx`, ~строка 68). Сделать его вкладкой
  внутри «Администрирование» с названием «Диагностика запуска и обновлений».
  Права прежние (admin + `update_channel_manage`); прямая ссылка `#/readiness`
  продолжает работать — редирект на новую вкладку.
- Вверху страницы короткое пояснение: «Здесь видно, всё ли в порядке с
  установкой: база данных, резервные копии, обновления, лицензия. Если что-то
  красное — сделайте отчёт ярлыком "HR Manager — отчёт для разработчика" и
  отправьте его разработчику.»

## Тесты
- Vitest: новые названия полей; блок «Что произойдёт» меняется при смене каждого
  поля; сообщения про тихие часы и неполную форму; пункт меню исчез, вкладка в
  администрировании есть, `#/readiness` редиректит, не-админ её не видит.
- Если добавлен endpoint preview — backend-тест, что он ничего не пишет в outbox.
- Весь CI зелёный, существующие тесты не ослаблять.
