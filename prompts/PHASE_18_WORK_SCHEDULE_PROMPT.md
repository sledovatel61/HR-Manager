# Задача: «График выхода на работу» (Этап 18, обязателен для пилота)

Репозиторий: https://github.com/sledovatel61/HR-Manager
База: `main` @ `f3430a9f8afb0e35be45260df19f34559568223e` (или свежий `main`).
Ветка `arena/<id>-work-schedule`, один PR в `main`. Параллельно другой агент
делает установщик (`prompts/PILOT_FINAL_PROMPT.md`), его файлы
(`installer/`, `infra/windows/`) не трогай.

## Зачем

Пилот делается для HR-менеджера на массовом подборе. Кандидат проходит этапы
(`new` → … → `offer` → `hired` «Оформлен» → `started` «Вышел»). Сейчас график
выходов HR ведёт вручную в Google-таблице: дата-разделитель («10 авг.»), под
ней строки людей, которые выходят в этот день. Колонки такие:
`№ | ФИО | Время | Организация | Отдел | Должность | Смена | Комментарий`.
Примеры значений: организации «ООО Авион», «ОП Авион», «ИТЦ»; отделы
«Производственный цех Сокол», «Транзитный склад»; смена «1 смена»/«2 смена»;
комментарий «при наличии места», «проходит медосмотр 13-го». Иногда вместо
кандидата стоит служебная строка: «Увольнение 13:00–14:00», «перевод», «отработка
грузчик». Полное описание — `ROADMAP.md`, «Этап 18».

Цель: HR ставит кандидату дату выхода в карточке, а кандидат сам попадает в
отдельную вкладку «График выхода». Эту вкладку можно открыть, отфильтровать,
выгрузить в Excel и распечатать.

## Что сделать

### Данные (backend, миграция `0016`)
- У кандидата новые необязательные поля: `start_date` (дата), `start_time`
  (время, необязательно), `start_organization`, `start_department`, `shift`,
  `start_comment` (короткие строки с разумными лимитами). Поле `position`
  переиспользовать, не дублировать.
- Дату можно ставить на этапах `offer`, `hired`, `started`. При переводе в
  `started` дата обязательна: если её нет, сервер отвечает 422 с русским текстом,
  а UI просит указать дату.
- Если кандидат ушёл в `rejected`/`fired` или удалён (soft delete), из графика он
  не пропадает молча. Правило: удалённые скрыты всегда; `rejected` показываются с
  пометкой «не вышел» и по умолчанию отфильтрованы (переключатель «показать
  отказавшихся»).
- Служебные строки без кандидата — отдельная сущность `schedule_entry`: дата,
  время/интервал, текст, организация, отдел, комментарий, автор. Создаёт,
  правит и удаляет только тот, у кого есть права на график.
- Все изменения даты/времени и служебных строк пишутся в существующий аудит
  (было → стало, кто, когда).
- Права — существующая модель: HR видит своих кандидатов (owner), а тот, у кого
  есть scope «все кандидаты» или `pilot_full_access`, видит всех. Ничего нового
  в RBAC не выдумывать: переиспользовать текущие проверки доступа к кандидатам.
- API: `GET /api/work-schedule?from&to&organization&department&position&shift
  &owner&stage&q&include_rejected` — сервер фильтрует и сортирует по дате, потом
  по времени (строки без времени — в конце дня). Плюс CRUD служебных строк и
  `GET /api/work-schedule/export.xlsx` с теми же фильтрами.
- Excel: создать настоящий `.xlsx` (например, через `openpyxl` — добавь
  зависимость с закреплённой версией). Формат — как в образце: строка-заголовок
  дня (жирная, с заливкой, «пн, 10 авг. 2026»), под ней пронумерованные строки,
  ширина колонок подогнана, альбомная печать, повтор шапки на каждой странице.
  Защита от CSV/формул-инъекций: значения, начинающиеся с `= + - @`, пишутся как
  текст.

### Интерфейс (frontend)
- В карточке кандидата блок «Выход на работу»: дата (календарь), время,
  организация, отдел, смена, комментарий. Для организации/отдела/смены —
  подсказки из уже введённых значений (autocomplete), без отдельного справочника.
- При перетаскивании в Kanban на «Вышел» без даты открывается маленькое окно
  «Укажите дату выхода».
- Новый пункт меню «График выхода» (для всех, кто работает с кандидатами):
  - сверху период (по умолчанию текущая неделя и следующая; кнопки «Эта неделя»,
    «Следующая», «Месяц», «Свой период»), фильтры и поиск;
  - таблица по дням: дата-разделитель с числом выходов за день, строки
    `№ | ФИО | Время | Организация | Отдел | Должность | Смена | Комментарий |
    Ответственный HR`; служебные строки выделены цветом;
  - клик по ФИО открывает карточку кандидата; кнопка «+ Служебная запись» в
    каждом дне;
  - дату/время можно поменять прямо в строке (быстрый перенос), с аудитом;
  - кнопки «Скачать Excel» и «Печать». Печать через отдельный print-CSS: только
    таблица, без меню, альбомная ориентация, дневные блоки не рвутся между
    страницами там, где это возможно. Выгрузка и печать совпадают с тем, что на
    экране при текущих фильтрах.
- Весь текст — на русском, в стиле существующего интерфейса.

## Тесты (обязательно)
- Backend: сохранение/перенос даты, 422 при `started` без даты, служебные
  строки, фильтры, сортировка, права (HR не видит чужих, админ видит всех),
  исключение удалённых, `rejected` с флагом, аудит, xlsx открывается
  (`openpyxl.load_workbook`) и содержит те же строки, что API, защита от
  формул-инъекций. Миграция `0016` проходит upgrade/downgrade с base на
  PostgreSQL (integration job).
- Frontend (Vitest): блок в карточке, модалка при переходе в «Вышел», группировка
  по дням, фильтры, кнопки экспорта/печати.
- Весь CI зелёный (все существующие jobs).

## Ограничения
