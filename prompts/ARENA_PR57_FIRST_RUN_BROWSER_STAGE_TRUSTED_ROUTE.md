# Браузерный этап первого запуска: маршрут для preview/redeem

Статус: **открыто.** Продолжение `ARENA_PR57_FIRST_RUN_CLAIM_404_ROOT_CAUSE_AND_FIX.md`.
Правка локального агента (claim напрямую в бэкенд на loopback-порту) верная и
необходимая, но **недостаточная** — и он это нашёл первым.

---

## 1. Почему прямого claim не хватает

Проверено ревьюером по коду на `6ae189a`:

- `backend/app/routers/setup.py:334` — `/setup/owner/preview` вызывает
  `loopback_client_ok` и при отказе отдаёт 404.
- `backend/app/routers/setup.py:363` — `/setup/owner/redeem` делает то же самое.
- Браузер обращается к ним **относительными** путями `/api/setup/owner/*`, то есть
  через nginx.

Значит после успешного claim движок открывает браузер, SPA дёргает `preview` —
и получает 404 по той же причине: nginx затирает `X-Real-IP` адресом шлюза
контейнерной сети. Экран «Первый запуск» не откроется.

## 2. Почему адрес источника в принципе не работает для браузера

- Единственный путь к бэкенду — nginx (`compose.pilot.yml`: у `backend`
  `ports: !reset []`).
- `frontend/nginx.conf:13` — `set $backend_upstream http://backend:8000;`.
  Конфиг **статический**, запечён в образ (`frontend/Dockerfile:18` —
  `COPY nginx.conf ...`), env-подстановки в рантайме нет. Значит менять его можно
  только пересборкой образа, и нельзя сделать зависимым от `HRM_PILOT_BIND`.
- При публикации порта Docker и loopback-клиент, и клиент из локальной сети
  приходят в контейнер с **одинаковым** `$remote_addr` (шлюз контейнерной сети).
  nginx **не может** их различить.

Вывод: для браузерного этапа определение «клиент локальный» по адресу невозможно
в принципе. Нужен маршрут, где «локальность» обеспечивается не заголовком клиента.

## 3. Решение: два слушателя nginx

Оставить существующую публикацию и добавить вторую, **всегда** на loopback:

```yaml
frontend:
  ports: !override
    # Существующий слушатель: loopback по умолчанию, 0.0.0.0 при доступе по сети.
    - "${HRM_PILOT_BIND:-127.0.0.1}:${HRM_PILOT_PORT:-8080}:8080"
    # Новый слушатель: только loopback. Сюда движок открывает первый запуск.
    - "127.0.0.1:${HRM_PILOT_TRUST_PORT:-8082}:8081"
```

nginx слушает 8080 и 8081 и по-разному помечает источник:

```nginx
# Слушатель общий (loopback или LAN). Маркер = реальный адрес клиента.
server {
    listen 8080;
    ...
    location /api/ {
        proxy_pass $backend_upstream;
        proxy_set_header X-Real-IP $remote_addr;   # без изменений
    }
}

# Слушатель только для loopback. Docker гарантирует, что до него не дотянется
# клиент из сети: порт привязан к 127.0.0.1. Поэтому пометка loopback здесь
# достоверна — это факт, обеспечиваемый Docker, а не заявление клиента.
server {
    listen 8081;
    ...
    location /api/ {
        proxy_pass $backend_upstream;
        proxy_set_header X-Real-IP 127.0.0.1;
    }
}
```

Движок во время первого запуска открывает браузер на
`http://127.0.0.1:<HRM_PILOT_TRUST_PORT>/#setup=<тикет>`. Относительные вызовы
`/api/...` уходят на тот же слушатель, помечаются loopback, `preview` и `redeem`
проходят. Обычная работа после настройки — на прежнем порту.

### Почему это безопасно

- пометку ставит **nginx по тому, на каком слушателе пришёл запрос**, а не
  клиентский заголовок;
- loopback-слушатель привязан к `127.0.0.1`, поэтому клиент из локальной сети
  **физически не может к нему подключиться** — Docker откажет на уровне bind;
- клиентский `X-Real-IP` по-прежнему затирается на общем слушателе;
- loopback-проверка бэкенда остаётся без изменений;
- тикет по-прежнему обязателен (см. §5).

### Обязательное изменение теста

`infra/windows/tests/pilot-final.tests.ps1:345` требует отсутствия строки
`proxy_set_header X-Real-IP 127.0.0.1;`. После правки утверждение должно стать
структурным, а не буквальным:

- в общем слушателе `X-Real-IP $remote_addr;` — присутствует;
- жёсткая пометка `127.0.0.1` встречается **только** внутри серверного блока,
  который слушает loopback-порт;
- порт loopback-слушателя в публикации compose привязан к `127.0.0.1`;
- клиент из сети по-прежнему отвергается (отдельный тест на `_is_loopback`).

Запрещено: убирать проверку loopback у бэкенда, доверять клиентскому
`X-Real-IP` на общем слушателе, помечать loopback всех клиентов.

## 4. Если второй порт нежелателен — запасной вариант

Отдать у `preview`/`redeem` проверку адреса и опираться только на тикет.
Допустимо, но это ослабление защищённости: тикет перестаёт быть вторым барьером.
Принимать только если владелец согласует, и тогда — с явной записью в отчёте,
какая защита снята и почему. Рекомендация ревьюера — вариант из §3.

## 5. Что уже защищает браузерный этап (проверено)

- `TICKET_BYTES = 32` (`setup_owner.py:50`) → `secrets.token_urlsafe(32)`,
  256 бит, неугадываемо;
- тикет хранится хешем, одноразовый, TTL 15 минут
  (`pilot_ticket_ttl_minutes`);
- выдаётся только успешным claim, который теперь идёт на loopback-порт бэкенда и
  требует токен обмена 64 hex;
- тикет travels только во фрагменте URL — не уходит в Referer и не попадает в
  журналы nginx;
- `redeem_owner` повторно проверяет `_first_run_enabled` и `_users_exist`.

Поэтому §3 не открывает дыру: маркер loopback — не секрет, а подтверждённая Docker
топология.

## 6. Порядок работ

1. Два слушателя nginx + открытие браузера первого запуска на loopback-слушатель.
2. Пересборка образа фронтенда (конфиг запечён в образ — без пересборки не
   применится).
3. Структурная правка теста `pilot-final.tests.ps1:345` + новый тест на отказ
   сетевому клиенту.
4. Классификация состояний токена из предыдущего документа (она ещё не закрыта).
5. Прогон на **обоих** хостах: Windows PowerShell 5.1 и pwsh. Сейчас 353/353 на
   5.1; на pwsh были два падения supervisor-тестов, связанных с датами —
   окончательный результат повторного прогона не подтверждён, оба хоста зелёными
   не объявлять до сверки.
6. Изолированная чистая установка: отдельное имя проекта, отдельный StateDir,
   **свободный порт**, отдельные теги образов. Сборка с записанным происхождением
   (коммит, дата, SHA256 `Setup.exe` и манифеста).
7. Критерий успеха: код выхода 0; браузер сам открыл экран «Первый запуск HR
   Manager»; владелец создан через этот экран; старые стек и тома не тронуты.
