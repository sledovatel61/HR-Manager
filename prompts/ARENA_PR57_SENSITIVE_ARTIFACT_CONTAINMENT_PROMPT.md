## Часть 1. Немедленное удаление из tip `main` (containment)

**Механизм PR-ветки здесь недостаточен.** Удаление путей в ветке PR убирает их только из
результата слияния при мерже — это не containment. Файлы должны исчезнуть из `main` **сейчас**.

Push в `main` может сделать только владелец (агенты в этой setup привязаны к своим веткам).
Команды для владельца (локально или через веб-интерфейс — так же, как файл туда попал):

```bash
git fetch origin && git checkout main && git reset --hard origin/main
git rm tests/pr57-live-bb14399-evidence.zip \
       HR-Manager-report-2026-10-14_14-45-31.zip \
       tests/PR57-reviewer-evidence-20261015-092151.txt \
       pr57-live-start.log
git commit -m "chore(security): remove leaked evidence artifacts from main tip (containment)"
git push origin main
```

Требования к коммиту:

- изменены **ровно четыре пути**, все в статусе `D`; ни один другой файл не тронут;
- до push: `git diff --cached --name-status` и `git status --porcelain` (должно быть чисто);
- после push: записать SHA коммита удаления и сверить, что в tip `main` этих путей нет
  (`git ls-tree -r --name-only origin/main | grep -E 'pr57-live|HR-Manager-report'` → пусто).

**Что делает исполнитель (в своей ветке, без push в main):**

1. Перепроверить аудит после удаления владельцем — тем же способом (список критериев выше),
   чтобы убедиться, что не появилось новых чувствительных файлов.
2. Влить очищенный `main` в ветку PR `arena/3cadc6a9-hr-manager` обычным merge (**не** rebase,
   **не** force-push) — ветка и merge-ref должны унаследовать удаление.
3. Проверить дерево слияния `main` + head PR:
   ```bash
   TREE=$(git merge-tree --write-tree origin/main HEAD)
   git ls-tree -r --name-only "$TREE" | grep -E '\.(dump|zip|log)$|evidence'   # ожидание: пусто
   C=$(git commit-tree "$TREE" -p origin/main -p HEAD -m "simulated CI merge ref")
   rm -rf /tmp/mc && git worktree add -q --detach /tmp/mc "$C"
   cd /tmp/mc && git ls-files -ci --exclude-standard   # ожидание: пусто
   cd /tmp/mc && git status --porcelain                 # ожидание: пусто
   ```
4. Убедиться, что CI остаётся зелёным (8/8), и зафиксировать в PR #57 новый head SHA.
5. В описание PR добавить раздел про инцидент: что раскрыто, что удалено из tip, что ротация
   выполняется владельцем, что история ещё не очищена. **Не** вкладывать в PR дампы, логи,
   `process-info.json` и любые evidence — они остаются в ACL-ограниченном локальном каталоге.

## Часть 3. Переписывание истории (владелец, отдельный этап после containment)

Удаление из tip не убирает объекты из истории. Для публичного репозитория:

1. Сделать backup текущего состояния репозитория; записать SHA коммита удаления и SHA
   перечисленных blob (таблица выше) — они нужны для обращения в поддержку.
2. Переписать историю `git filter-repo --invert-paths --path <путь>` (или BFG
   `--delete-files`) по всем четырём путям, во всех refs.
3. Согласованный force-push; удалить/пересоздать ветки и refs, которые удерживают старые объекты.
4. Обратиться в GitHub Support с SHA blob/коммитов для purge закешированных представлений
   и архивов.
5. Проверить результат: `git rev-list --objects --all | grep -E 'pr57-live|HR-Manager-report|PR57-reviewer-evidence'`
   → пусто; плюс проверка через GitHub API (дерево `main`, поиск по SHA blob).
6. Повторить Parts 1–2 аудит после переписывания.
