## Часть 2. Почему на этом ПК установщик больше не проверяем

Подтверждено три раза, и ни одна причина не относится к нашей правке:

1. Inno Setup помнит прошлый каталог в реестре (`HKCU\...\Uninstall\...
   InstallLocation`) и ставит туда снова, даже без `/DIR=`. Убрать ключ
   недостаточно — нужна очистка реестра, то есть ещё более глубокая подготовка.
2. Имя Compose-проекта захардкожено и делится с живым пилотом, тома общие.
   Каталоги этого не изолируют.
3. Две половины не согласованы по путям: `installer.iss:265` жёстко берёт
   `%LOCALAPPDATA%\HRManager`, а `installer.iss:120` не передаёт движку
   `-InstallDir`.

Каждый прогон — это риск для рабочего пилота и отчёт про окружение, а не про
программу.

## Часть 3. Что доказано и чего не хватает

**Доказано живьём, на изолированном стеке `hrm-firstrun-test`:**

- `POST /setup/owner/claim` с `X-Real-IP: 127.0.0.1` → **HTTP 201 и тикет**,
  а не 404. Это и есть починенный дефект.
- Браузер по доверенному адресу показал **экран первого запуска с формой
  регистрации**.
- Владелец создан: ровно один пользователь, роль admin.
- Сетевой запрос с подделанным `X-Real-IP: 127.0.0.1` через публичный слушатель
  → **404**. Отказ выполняется раньше проверки владельца и токена, то есть
  доказан именно отказ по сети.
- Повторный claim с тем же токеном → **409**, второй владелец не создаётся.

**CI на `ca87e13`:** девять заданий из девяти зелёные, включая
`Compose stack smoke test`. Bindings сверены по артефакту `pilot-port-merge`:
в режиме LAN доверенный порт 18002 и порт claim 18001 остаются на `127.0.0.1`.

**Не проверено:** прогон `Setup.exe` на стандартных путях с чистой машины.
Оркестровка установщика при этом покрыта 354 автоматическими тестами.

## Часть 4. Незакрытое замечание (не блокирует мерж)

Движок не открыл браузер, хотя Setup передал `-OpenBrowser`. Механизм в
`Common.psm1`, функция `Invoke-HrmOpenBrowser`:

```powershell
$open = (Test-HrmInteractive -or $global:HrmOpenBrowser -or $env:HRM_OPEN_BROWSER -eq "1")
```

При `-OpenBrowser` должен открываться. В журнане — ветка «браузер не
открывается», значит `$open` был ложным. **Смертельного нет:** ссылка всегда
пишется в защищённый `first-run-url.txt`, по ней регистрация открывается вручную,
и на изолированном стеке эта ссылка работала. Разобраться стоит, но это не
причина блокировать мерж.
