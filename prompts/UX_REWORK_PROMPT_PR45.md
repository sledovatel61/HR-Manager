## 3. P1 — функциональный пробел: `.docx` / `.pdf` по-прежнему не импортируются

Замечание владельца: «нет тех шаблонов, что я уже положил
`C:\Users\User\Documents\HR\HR Manager Desktop\LLM\23.09.2026` там куча полезных файлов,
шаблоны которых можно было бы уже загрузить в этот раздел».

Сейчас `SUPPORTED_EXTENSIONS = (".txt", ".md", ".markdown", ".csv")`
(`backend/app/template_import.py:56`) — реальные файлы владельца отклоняются, то есть
конкретная просьба не закрыта.

Требования (не ломая существующую защиту):

* **`.docx`** — это ZIP с `word/document.xml`. Извлекать **только текст** (`<w:t>`), ничего
  не исполняя. Проверять, что это действительно ZIP с ожидаемой структурой. Защита от
  zip-bomb: лимит и на размер архива, и на суммарные распакованные байты.
* **`.pdf`** — **не** парсить «в нормальный текст». Либо честный отказ с внятной инструкцией
  («сохраните как .txt/.md/.docx и загрузите снова»), либо минимальное извлечение текстового
  слоя — но без half-parsed ерунды. Выбор обоснуй в отчёте.
* Расширить `SUPPORTED_EXTENSIONS`; сообщения об отказе должны называть принимаемые форматы.
* **Нельзя:** писать файл на диск, строить путь из имени, исполнять что-либо, увеличивать
  `MAX_UPLOAD_BYTES`.
* Аудит по-прежнему фиксирует формат и безопасное отображаемое имя, **никогда** — содержимое.
* Права: один `require_manage`; HR без гранта — 403.
* Тесты: happy path `.docx` (если делаешь), отказ `.pdf`/неизвестного расширения, отказ по
  размеру, отказ zip-bomb/бинарности, права, аудит без содержимого.
