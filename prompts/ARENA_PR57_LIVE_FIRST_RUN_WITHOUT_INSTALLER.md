# Финальный шаг: живой тест первого запуска БЕЗ установщика и без риска для пилота

Статус: CI `39378798415` на `ca87e13` — все девять заданий success.
Bindings из артефакта `pilot-port-merge` проверены ревьюером: 4/4 `ok=true`, в
режиме LAN доверенный порт 18002 и порт claim 18001 остаются на `127.0.0.1`.

**Установщик пересобирать не нужно.** Артефакт `pilot-setup-0.15.0-unsigned`,
ID 12244328090, 2 421 137 байт (ZIP), извлечённый EXE 2 954 033 байта. Хеши
сверены с GitHub digest и `SHA256SUMS.txt`.

**Остался один шаг: живой тест первого запуска.** Делается без установщика и без
какого-либо контакта с живым пилотом.

---

## Почему так, а не через установщик

Имя Compose-проекта захардкожено в движке (`Compose.psm1:7`, `:12`, флаг
`--project-name`), поэтому «чистая установка» на этом ПК неизбежно упирается в
живой пилот от 10.09. Но Compose можно вызвать **руками** с другим именем
проекта — правок кода не требуется, и получается полностью изолированный стек:
свои тома, свои порты, своя база без владельца.

Это проверяет именно тот дефект, ради которого всё делалось: получает ли браузер
окно регистрации вместо 404.

## Шаг 1. Временный env-файл

Взять за основу рабочий env пилота и поменять только порты и токен обмена:

```powershell
Copy-Item <StateDir-пилота>\pilot.env $env:TEMP\firstrun-test.env
```

В копии выставить:

```text
HRM_PILOT_BIND=127.0.0.1
HRM_PILOT_PORT=18080
HRM_PILOT_CLAIM_PORT=18081
HRM_PILOT_TRUST_PORT=18082
HRM_EXCHANGE_TOKEN=<новые 64 hex, не менее 43 символов>
```

Свежий токен обязателен: у живого пилота токен уже погашен, и на нём claim
вернёт 409 вместо 201.

## Шаг 2. Поднять отдельный стек

```powershell
docker compose -p hrm-firstrun-test `
  -f infra\docker-compose.yml -f infra\compose.pilot.yml `
  --env-file $env:TEMP\firstrun-test.env up -d
docker compose -p hrm-firstrun-test ps
```

Порты 18080/18081/18082 не должны пересекаться с живым пилотом. Живой пилот при
этом не трогается: другое имя проекта, другие тома.

## Шаг 3. Claim — точно как движок

Из кода движка (`Bootstrap.psm1`): `POST
http://127.0.0.1:<claimPort>/setup/owner/claim`, заголовок `X-Real-IP: 127.0.0.1`,
тело `exchange_token` + `surname` + `working_mode` + `timezone`. Успех — **201** и
поле `ticket`. 409 — владелец уже есть.

```powershell
$body = @{
    exchange_token = "<токен из шага 1>"
    surname        = "Приемка"
    working_mode   = "<режим из перечисления PilotWorkingMode>"
    timezone       = "Europe/Moscow"
} | ConvertTo-Json

$r = Invoke-RestMethod -Uri "http://127.0.0.1:18081/setup/owner/claim" `
    -Method Post -Body $body -ContentType "application/json" `
    -Headers @{ "X-Real-IP" = "127.0.0.1" }

$r.ticket      # должен быть непустым
```

**Это точка, где раньше был 404.** Если здесь 201 и тикет — корневая причина
устранена.

## Шаг 4. Браузер — точно как движок

Движок открывает `http://127.0.0.1:<trustPort>/#setup=<ticket>`. Сделать то же:

```powershell
Start-Process "http://127.0.0.1:18082/#setup=$($r.ticket)"
```

**Ожидание: экран «Первый запуск HR Manager» с окном регистрации** — фамилия,
режим работы, часовой пояс. Не экран ввода логина/пароля.

Заполнить и сохранить. Проверить, что владелец создан и приложение открывается.

## Шаг 5. Живой отказ сетевому клиенту — с одной машины

Второй компьютер не нужен. Перезапустить тестовый стек на `0.0.0.0`:

```text
HRM_PILOT_BIND=0.0.0.0
HRM_PILOT_PORT=18080
```

```powershell
docker compose -p hrm-firstrun-test -f infra\docker-compose.yml -f infra\compose.pilot.yml --env-file $env:TEMP\firstrun-test.env up -d
```

Найти сетевой IP этого ПК (`ipconfig`) и обратиться **по нему**, а не по
`127.0.0.1`, с подделанным заголовком:

```powershell
$ip = (Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -like "192.168.*" -or $_.IPAddress -like "10.*" } |
  Select-Object -First 1).IPAddress

$body = @{ exchange_token = "<СВЕЖИЙ токен>"; surname = "Сеть"; working_mode = "<режим>"; timezone = "Europe/Moscow" } | ConvertTo-Json
try {
    Invoke-RestMethod -Uri "http://${ip}:18080/setup/owner/claim" -Method Post -Body $body -ContentType "application/json" -Headers @{ "X-Real-IP" = "127.0.0.1" }
    "ОПАСНО: сетевой клиент прошёл"
} catch {
    "ОТКАЗАТО (ожидаемо): $($_.Exception.Response.StatusCode.value__)"
}
```

Токен должен быть свежий: после успешного claim предыдущий погашен.

**Ожидание: отказ.** Через nginx заголовок `X-Real-IP` перезаписывается на
`$remote_addr` — сетевой адрес, не loopback. Если запрос проходит — правка не
достигла цели, сообщить немедленно.
