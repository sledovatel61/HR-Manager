# Промпт для AI-агента: Этап 1

Ты работаешь в репозитории HR Manager. Сначала прочитай `agents.md`, `PRODUCT_SPEC.md` и `ROADMAP.md`. Не используй старый PyQt6/SQLite-прототип как основу и не создавай локальную SQLite-БД.

## Цель этапа

Создать запускаемый технический каркас сетевого приложения: FastAPI + SQLAlchemy 2 + Alembic + PostgreSQL, React + TypeScript + Vite, Docker Compose, health-check, базовые тесты и CI-ready команды. Реальную бизнес-функциональность кандидатов на этом этапе не реализовывать.

## Обязательно сделать

1. Выбрать и зафиксировать структуру `backend/`, `frontend/`, `infra/`, `docs/`, `tests/`.
2. Добавить pinned или разумно ограниченные зависимости и `.env.example` без секретов.
3. Поднять PostgreSQL через Docker Compose с volume и healthcheck.
4. Реализовать backend endpoint `GET /health` с проверкой доступности приложения и БД.
5. Реализовать минимальную frontend-страницу с понятным состоянием backend/database.
6. Добавить Alembic и первую безопасную миграцию-заготовку.
7. Добавить команды запуска, тестов, lint/typecheck в README.
8. Добавить тесты health endpoint и тест, который не допускает подключения к production без обязательной конфигурации секретов.
9. Добавить базовый CI workflow, который устанавливает зависимости и запускает проверки.
10. Добавить `.gitignore`: `.env`, базы, backup, логи, node_modules, build artifacts.

## Ограничения

- Не хранить пароли, токены и реальные персональные данные.
- Не делать hard delete и не добавлять фиктивные endpoint-ы.
- Не использовать SQLite даже как production fallback; допустим SQLite только для изолированных unit-тестов, если это явно документировано.
- Не добавлять микросервисы без необходимости.
- Не менять ТЗ молча.

## Критерии приёмки

- `docker compose up --build` запускает PostgreSQL, backend и frontend.
- `GET /health` возвращает успешный ответ только при доступной БД.
- backend tests проходят.
- frontend build/typecheck проходят.
- CI-файл синтаксически корректен.
- README позволяет новому разработчику запустить проект с нуля.

В конце выдай отчёт: изменённые файлы, архитектурные решения, команды проверки и их полный результат, известные ограничения. Не переходи к этапу 2.
