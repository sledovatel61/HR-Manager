## Приоритеты

### P0 — сначала исправить и доказать тестами

1. **Календарь.** При создании события под admin/manager список исполнителей не должен быть пустым, если есть активный пользователь с ролью HR. Исправь загрузку, права, обработку пустого ответа и понятное состояние «HR-пользователь не создан/не активен». Поле даты и времени напоминания должно быть реально доступным: выбор, очистка, валидация относительно начала события, часовой пояс и локализация. Валидное событие должно сохраняться.
2. **Единая связь событий и напоминаний.** Создание из календаря, карточки кандидата и раздела напоминаний должно использовать согласованный доменный контракт. После создания событие видно в календаре, а связанное напоминание — в «Напоминаниях». Не допускай дублей и рассинхронизации статусов.
3. **Кандидат в напоминании.** Сохрани вариант «Без кандидата», но добавь поиск кандидатов по ФИО/телефону/email с серверной фильтрацией и проверкой прав. Связанные объекты должны открывать карточку кандидата.
4. **Мои правила.** Исправь загрузку опубликованных списков/версий. Если списков нет, покажи понятное пустое состояние с переходом к созданию списка, а не пустой обязательный select. Сервер должен повторно проверять права, публикацию и версию.

### P1 — после стабилизации P0

5. **Воронка кандидатов.** Переименуй пользовательское `Kanban` на согласованное русское название во всех местах. Перенос карточки из первого этапа в последний должен выполняться за одно действие без ручного последовательного горизонтального скролла: быстрый выбор этапа и/или автопрокрутка DnD. Сохрани клавиатурную альтернативу, optimistic update, rollback и обработку ошибок.
6. **Списки документов.** Переработай интерфейс в простой мастер: назначение списка, понятные строки документов, обязательность, пояснение, порядок, предпросмотр, черновик/публикация. Технический ключ и версионирование убери в расширенные сведения, не ломая существующие данные и связи.
7. **Шаблоны и методическая база.** Добавь безопасную загрузку поддерживаемых файлов, категории для документов/чек-листов/вопросников/памяток/скриптов, поиск, понятные подсказки и предпросмотр. Материалы из `C:\Users\User\Documents\HR\HR Manager Desktop\LLM\23.09.2026` сначала инвентаризируй и проверь на персональные данные/форматы; не зашивай содержимое в код и не импортируй автоматически без проверки.
8. **Навигация.** Сгруппируй редко используемые разделы в «Настройки»: уведомления, правила, обновления, лицензия, администрирование, пользователи, интеграции, контент и документы. Серверные проверки ролей не заменять скрытием пунктов меню.

## Обязательные критерии реализации

- Для каждого блока есть happy-path, ошибочный сценарий и тесты прав доступа.
- Нет пустых обязательных списков без объяснения и действия восстановления.
- Нет необъяснимых disabled-полей.
- Не считать наличие кнопки доказательством работы API: проверить реальный запрос, БД и повторную загрузку страницы.
- Проверить admin, manager и обычного HR на чистом локальном Compose-стенде.
- Проверить даты, локальное время, Europe/Moscow, граничные значения и ошибки сети.
- Не удалять существующие версии документов, шаблоны, кандидатов или связи.
- Не раскрывать секреты и не коммитить `.env`, дампы или реальные персональные данные.
