## 1. Единственный оставшийся дефект: одна реальная пара всё ещё вне гейта

`.queue-link` — кнопка «Непрочитанных уведомлений» на экране «Моя очередь».

| Файл | Строка | Что |
| --- | --- | --- |
| `frontend/src/features/queue/queue.css` | 219 | `.queue-link {` |
| `frontend/src/features/queue/queue.css` | 228 | `color: var(--accent-default)` |
| `frontend/src/features/queue/queue.css` | 234–236 | `.queue-link:hover { background: var(--surface-selected-hover) }` |
| `frontend/src/features/queue/MyQueuePage.tsx` | 275 | `<button type="button" className="queue-link" …>` — реально рендерится |

В состоянии `:hover` текст кнопки имеет `color: var(--accent-default)` (правило
`:228` не перебито), а фон — `var(--surface-selected-hover)`.

**Факт: light `3.88:1`, dark `4.89:1`. Ожидание AA: ≥ 4.5:1.**

То есть в светлой теме при наведении курсора на кнопку «Непрочитанных
уведомлений» её текст проваливает AA. Пара реальна и доступна пользователю.

### Почему она не попала в гейт

`scripts/measure-contrast.py:123-126`:

```python
("--surface-selected-hover", None): (
    "grep -rn 'var(--surface-selected-hover)' frontend/src → единственное "
    "использование: queue.css:235 .queue-link:hover, цвет — --accent-default"
),
```

Эта запись лежит в `ABSENT_EVIDENCE`, то есть объявляет пару отсутствующей. При
этом **её собственный текст называет точную пару, которую надо мерить**:
поверхность `--surface-selected-hover`, место `queue.css:235`, цвет
`--accent-default`. Пара `("--surface-selected-hover", "--accent-default")` при
этом в `PAIR_EVIDENCE` отсутствует — и не измеряется.

Это ровно та же механика, что и в прошлый круг, только на один уровень глубже:
тогда исключение обосновывалось непроверенным допущением «таких пар в вёрстке
нет», теперь — записью, которая сама содержит доказательство существования пары.

Полный перебор это подтверждает: на текущем коде в светлой теме **единственная**
реально существующая провальная пара — `--accent-default` на
`--surface-selected-hover` = 3.88:1. Остальные 14 провальных пар перебора в
вёрстке не встречаются, и их исключение обоснованно.

## 2. Что сделать

### 2.2 Исправить контраст (выбрать один вариант)

**(а) Не осветлять фон на hover у `.queue-link`.** В `queue.css` заменить
`background: var(--surface-selected-hover)` на затемняющий токен состояния, как
сделано для остальных состояний тёмной темы, либо на
`var(--surface-hover)` — но проверить, что `--surface-hover` в светлой теме даёт
≥ 4.5:1 с `--accent-default` (сейчас `accent-default` на `hover` = 4.34:1, то есть
тоже недостаточно). Самый предсказуемый путь — затемняющая подложка.

**(б) Сделать hover-состояние `.queue-link` непрозрачным.** Например, отдельный
токен `--accent-subtle-hover` с плотным значением из палитры, аналогично
`--accent-subtle`. Тогда контраст перестаёт зависеть от mesh и от базовой
поверхности. Это самый надёжный вариант, и он в духе уже сделанного: базовое
состояние `.queue-link` (`--accent-subtle`) как раз непрозрачное и даёт 4.66:1.

**(в) Поднять цвет текста на hover.** Добавить в `queue.css` в правило
`.queue-link:hover` строку `color: var(--accent-on-subtle)`. Минус: цвет текста
меняется при наведении — это может выглядеть как подмигивание, проверять глазами.

Критерий приёмки: `python3 scripts/measure-contrast.py` даёт 0 провалов **и**
ненулевой код возврата отсутствует, при этом пара
`("--surface-selected-hover", "--accent-default")` измеряется в гейте.

## 3. Как ревьюер проверит

```bash
# 1. Пара в гейте
grep -n '"--surface-selected-hover", "--accent-default"' scripts/measure-contrast.py
grep -c '"--surface-selected-hover", None' scripts/measure-contrast.py   # ожидание 0

# 2. Скрипт зелёный
python3 scripts/measure-contrast.py | tail -8

# 3. Пара посчитана вручную (ожидание >= 4.5:1 в обеих темах)
python3 - <<'PY'
import importlib.util
spec=importlib.util.spec_from_file_location("mc","scripts/measure-contrast.py")
mc=importlib.util.module_from_spec(spec); spec.loader.exec_module(mc)
for theme in ("light","dark"):
    T=mc.tokens_for(theme)
    canvas=mc.resolve(T["--surface-canvas"],T)[:3]
    mo=float(T.get("--mesh-opacity","0.5"))
    worst=99
    for b in ("--blob-1","--blob-2","--blob-3"):
        col=mc.resolve(T[b],T); bl=mc.over(col[:3]+(col[3]*mo,),canvas)
        for base in ("--surface-app","--surface-raised","--surface-glass"):
            if base not in T: continue
            bg=mc.over(mc.resolve(T["--surface-selected-hover"],T), mc.over(mc.resolve(T[base],T), bl))
            worst=min(worst,mc.contrast(mc.over(mc.resolve(T["--accent-default"],T),bg),bg))
    print(f"{theme}: accent-default на selected-hover = {worst:.2f}:1  {'AA' if worst>=4.5 else 'FAIL'}")
PY

# 4. В теле PR нет самоопровергающегося исключения
gh api repos/sledovatel61/HR-Manager/pulls/49 --jq .body | grep -c '3.88'
```

## 4. Правило, которое больше не обсуждается

Запись в списке «этого в вёрстке нет» — это **измерение**, и оно должна содержать
доказательство отсутствия, а не доказательство наличия. Если обоснование
исключения называет файл, строку и цвет текста — это не отсутствие пары, это
найденная пара, которую забыли померить.

Проверка перед коммитом такая: прочитай своё же обоснование и ответь на вопрос
«если я прав, то какую именно пару оно описывает?» Если ответ содержит
поверхность и цвет — пара есть, и она идёт в гейт.

одиннадцать реальных пар, гейт снова честный, размеры и тело PR сходятся с
фактом до байта. Осталась одна пара — и она ровно про то, чтобы не объявлять
проблему отсутствующей, когда собственное обоснование её описывает.
