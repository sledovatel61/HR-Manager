### Это регрессия, а не предсуществующий баг

На `main` те же элементы и те же классы, но тёмные токены были **непрозрачными**:

| Токен (тёмная тема) | `main` | ветка `c7c40da` |
| --- | --- | --- |
| `--surface-raised` | `var(--palette-slate-800)` — непрозрачный | `rgba(255, 255, 255, 0.09)` |
| `--surface-app` | `var(--palette-slate-900)` — непрозрачный | полупрозрачный |
| `--surface-selected` | `rgba(79, 94, 234, 0.18)` | `rgba(56, 189, 248, 0.18)` |

На main mesh не просвечивает сквозь `.calendar-chip` и `.table-wrap`, поэтому пара 1
даёт **4.65:1** и проходит AA. В ветке поверхность стала полупрозрачной, пятно
подсвечивает фон, и та же пара падает до 3.58:1. Разметка, классы и роль цвета
текста не менялись — поменялись только токены поверхности.

Именно поэтому твоя правка пятен (`#0284c7→#0369a1`, `#4f46e5→#4338ca`,
`#0891b2→#0e7490`) закрыла гейт до 4.82:1, но **не закрыла состояния**: слой
`--surface-selected` (`rgba(56,189,248,0.18)`) сам по себе светлый и поверх
полупрозрачной `raised` поднимает фон сильнее, чем любое пятно.

## 2. Что сделать

### 2.1 Исправить контраст (выбрать один вариант, обосновать в PR)

Не надо делать всё сразу — выбрать одно и написать, почему.

**(а) Сделать выделенные поверхности плотнее.** `--surface-selected` и
`--surface-selected-hover` в тёмной теме заменить с `rgba(56,189,248,α)` на

**(б) Затемнить третичный/вторичный текст тёмной темы.** `--text-tertiary`

`raised + selected`. Минус: третичный текст на обычных поверхностях станет тусклее
необходимого.

**(в) Не класть tertiary/secondary на выделенные поверхности в этих двух местах.**
Для `.calendar-chip-time` — поднять до `--text-secondary`; для ячейки таблицы в

**Критерий приёмки:** `python3 scripts/measure-contrast.py` даёт 0 провалов **и** с

### 2.3 Исправить тело PR

Два места в теле PR теперь неверны:

1. **Про состояния.** Фраза «таких пар в вёрстке нет» — удалить. Заменить на

   сделано и каков результат. Не указывать «Провалов AA: 0», если состояния не
   меряются гейтом.
2. **Про md5 body.** В теле PR написано:

   > Не могу подтвердить `f1a9c5f9be98` для body из ревью. Перебрал срезы: `<body>`
   > до `</body>`, до `</html>`, до первого `<script>`, inner HTML с и без
   > script-блоков, с нормализацией пробелов и без комментариев — ни один не даёт
   > такого значения.

   **Это неверно.** Значение воспроизводится одной командой:

   ```bash
   python3 -c "import re,hashlib;t=open('design/mockups/bento-arctic.html',encoding='utf-8').read();print(hashlib.md5(re.search(r'<body.*?</body>',t,re.S).group(0).encode()).hexdigest()[:12])"
   ```

   Вывод: `f1a9c5f9be98`. Причина расхождения с твоим `2fad191b30bb`: `sed -n

   символам. Ты перебирал срезы через `sed` и не попробовал регулярное выражение
   по всей строке — а им это значение уже получено в твоём собственном коммите
   `65c3761`, где такой Python-скрипт и его вывод есть в сообщении.

   Заменить абзац на measured-значение с командой. JS-срез `c1a79f9b937e` —
   подтверждён, оставить.

## 3. Как ревьюер проверит

```bash
# 1. Гейт считает и состояния
python3 scripts/measure-contrast.py | tail -6

# 2. Пары из §1 считаются вручную (ожидание >= 4.5:1 в тёмной теме)
python3 - <<'PY'
import importlib.util
spec=importlib.util.spec_from_file_location("mc","scripts/measure-contrast.py")
mc=importlib.util.module_from_spec(spec); spec.loader.exec_module(mc)
T=mc.tokens_for("dark")
canvas=mc.resolve(T["--surface-canvas"],T)[:3]
mo=float(T.get("--mesh-opacity","0.5"))
worst=99
for b in ("--blob-1","--blob-2","--blob-3"):
    col=mc.resolve(T[b],T); bl=mc.over(col[:3]+(col[3]*mo,),canvas)
    bg=mc.over(mc.resolve(T["--surface-selected"],T), mc.over(mc.resolve(T["--surface-raised"],T), bl))
    r=mc.contrast(mc.over(mc.resolve(T["--text-tertiary"],T),bg),bg)
    worst=min(worst,r)
print(f"dark: text-tertiary на selected+raised = {worst:.2f}:1  {'AA' if worst>=4.5 else 'FAIL'}")
PY

# 3. md5 body
python3 -c "import re,hashlib;t=open('design/mockups/bento-arctic.html',encoding='utf-8').read();print(hashlib.md5(re.search(r'<body.*?</body>',t,re.S).group(0).encode()).hexdigest()[:12])"

# 4. В теле PR нет ложных утверждений
gh api repos/sledovatel61/HR-Manager/pulls/49 --jq .body | grep -c 'таких пар в вёрстке нет'
gh api repos/sledovatel61/HR-Manager/pulls/49 --jq .body | grep -c 'Не могу подтвердить'
```

Ожидание: оба `grep -c` дают **0**, команда из п.2 даёт **≥ 4.5:1**, md5 даёт
`f1a9c5f9be98`.

## 4. Правило, которое больше не обсуждается

**Исключение из проверки — это тоже решение, и оно требует такого же обоснования,
как и сама проверка.** Ты исключил состояния из гейта, потому что «в этом дизайне
выделение несёт акцентный текст, а не третичный», и написал это в PR как факт. В
макете это неверно в двух местах, и оба дают провал. Проверка, у которой гейт
настроен на проход, не защищает ни пользователя, ни следующего ревьюера.

Следствие практическое: когда в скрипте появляется комментарий вида «X в этом
дизайне не встречается» — это измерение, а не допущение. Перед тем как написать
такое, нужен `grep`, доказывающий его.

В остальном PR в хорошем состоянии: тело PR теперь точное, диагностика `gh pr edit`
найдена и верна, размеры сходятся до байта, базовая линия снята независимо. Остался
один пункт — и он ровно про то, чтобы не объявлять проблему решённой, исключив её
из замера.
