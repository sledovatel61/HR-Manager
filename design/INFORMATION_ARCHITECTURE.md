# INFORMATION_ARCHITECTURE.md — информационная архитектура HR Manager

## 1. Разделы верхнего уровня

| Раздел | Маршрут в прототипе | Видимость по роли |
|---|---|---|
| Главная | `#/home` | Все роли |
| Моя очередь | `#/queue` | Только `hr` |
| Кандидаты | `#/candidates` | Все роли |
| Kanban | `#/kanban` | Все роли |
| Календарь | `#/calendar` | Все роли |
| Аналитика | `#/analytics` | `manager`, `admin` |
| Шаблоны | `#/templates` | Все роли (публикация — только `admin`, см. `IMPLEMENTATION_GUIDE.md`) |
| Пользователи | `#/users` | Только `admin` |
| Журнал аудита | `#/audit` | `manager`, `admin` |
| Настройки | `#/settings` | Все роли |

Роль-зависимая видимость в прототипе — **чисто визуальная демонстрация**
паттерна; реальная защита прав обязана происходить на backend для каждого
запроса (см. `agents.md`, п. «Сервер проверяет права на каждый запрос»).

## 2. Глобальная навигация

- Постоянный левый сайдбар (тёмный, `--surface-sidebar`) с иконкой +
  подписью на каждый пункт; активный пункт подсвечен и помечен
  `aria-current="page"`.
- Внизу сайдбара — блок текущего пользователя (аватар-инициалы, имя, роль).
- Верхний topbar: заголовок текущего раздела, кнопка глобального поиска
  (открывает Command Palette), переключатели плотности/темы, колокольчик
  уведомлений, меню пользователя (профиль/выход).
- Skip-link ("Перейти к основному содержимому") — первый элемент в DOM,
  виден при фокусе клавиатурой.

## 3. Локальная навигация

- Внутри разделов со вкладками (карточка кандидата: Обзор/История/События)
  используется `Tabs` — паттерн WAI-ARIA "Tabs" с roving tabindex и
  стрелками влево/вправо.
- `Кандидаты` имеет собственный локальный переключатель "Таблица/Kanban"
  (сохраняет общий набор фильтров).

## 4. Breadcrumbs

Не используются как отдельный компонент: иерархия в HR Manager неглубокая
(раздел → карточка сущности, максимум 2 уровня), поэтому в качестве
"хлебных крошек" выступает заголовок раздела (topbar) + заголовок открытой
карточки (drawer). Добавление классических breadcrumbs в `IMPLEMENTATION_GUIDE.md`
отмечено как низкоприоритетное при появлении вложенных сущностей (например,
вакансия → кандидаты → карточка).

## 5. Глобальный поиск и Command Palette

Единая точка входа — Ctrl/Cmd+K из любого места приложения. Объединяет:
- навигацию по разделам;
- быстрые действия ("Создать кандидата", "Экспортировать список");
- поиск по кандидатам (имя, вакансия, город) с прямым переходом в карточку.

Также доступен как явная кнопка в topbar (для пользователей, не знающих
шорткат) — паттерн "не только через hover/шорткат" обязателен по
accessibility-требованиям промпта.

## 6. Быстрые и контекстные действия

- **Быстрые действия из таблицы** (hover-only показ, но также доступны по
  фокусу клавиатурой — `:focus-within`): передать кандидата, сменить статус.
- **Контекстные действия карточки:** передать (в шапке drawer), сменить
  этап (select), добавить взаимодействие/событие (кнопки в теле).
- **Kanban-карточка:** open по клику/Enter, перемещение этапом через select
  (keyboard-first alternative к drag-and-drop).

## 7. Фильтры и сохранённые представления

- Панель фильтров скрыта по умолчанию (иконка-переключатель), чтобы не
  перегружать топ страницы; при открытии показывает этап/ответственного/
  источник с возможностью сброса.
- Список сохранённых представлений (`SAVED_VIEWS` в mock-данных) показан как
  выпадающий список рядом с фильтрами — в реальной системе после выбора
  представления должны применяться его фильтры и сортировка (см. ограничение
  в `PERSONAS_AND_FLOWS.md`, флоу 4).

## 8. Уведомления

- Колокольчик в topbar открывает popover с последними уведомлениями
  (мок-данные): предстоящее собеседование, полученный кандидат, просроченное
  напоминание. Каждое уведомление имеет иконку + текст (не только цвет).
- Toast-уведомления (`aria-live="polite"`, `role="status"`) — для обратной
  связи по только что совершённому действию (передача кандидата, сохранение
  комментария, экспорт).

## 9. Переключение таблица/Kanban

Реализовано как сегментированный переключатель (`view-toggle`) из двух
`IconButton` с `aria-pressed`. Оба представления используют один и тот же
набор отфильтрованных кандидатов — переключение не сбрасывает фильтры.

## 10. Роль-зависимая навигация

Сайдбар рендерит только пункты, разрешённые текущей роли (см. таблицу выше).
Прямой переход по URL (`#/users` от имени HR) для сценария 17 показывает
`PermissionDeniedState вместо страницы — так демонстрируется, что скрытие
пункта меню — не единственный уровень защиты (текстовое пояснение — в
`ACCESSIBILITY.md` и `agents.md`).

## 11. Keyboard shortcuts

| Комбинация | Действие |
|---|---|
| `Ctrl/Cmd + K` | Открыть/закрыть Command Palette |
| `Esc` | Закрыть текущий диалог/drawer/палитру, вернуть фокус |
| `↑ / ↓` | Навигация по списку результатов в палитре |
| `Enter` | Выбрать активный пункт палитры / открыть кандидата (таблица, Kanban) |
| `← / →` (в фокусе на табах) | Переключение вкладок карточки кандидата |
| `Tab / Shift+Tab` | Стандартная навигация; зациклена внутри открытых модалок/drawer |

Ярлыки вида `G H`, `G Q` и т.д. в сайдбаре показаны как **визуальные
подсказки** для будущей реализации глобальных "goto"-шорткатов (по образцу
Linear/Superhuman) — сам обработчик клавиш для них в прототипе не включён,
чтобы не конфликтовать с полями ввода; это отмечено как задача этапа
внедрения в `IMPLEMENTATION_GUIDE.md`.

## 12. Поведение на разных ширинах экрана

Приоритет — desktop. Проверено вручную (пересчёт `vite build` + ручной обзор
верстки CSS Grid/Flexbox на контрольных breakpoints):

| Ширина | Поведение |
|---|---|
| 1440×900 | Основной эталонный layout — сайдбар 248px, контент до 1440px по центру |
| 1280×800 | Сайдбар сужается до 208px (`@media max-width: 1279px`), KPI-лента и home-grid переходят на более компактную сетку |
| 1024×768 | Таблицы получают горизонтальный скролл внутри контейнера (`overflow: auto`), Kanban — горизонтальный скролл колонок; login-экран скрывает декоративную левую панель (`@media max-width: 1024px`) |
| < 768 (мобильные, не основной режим) | Layout не оптимизирован специально, но: таблицы/канбан остаются горизонтально прокручиваемыми, модалки/drawer занимают почти весь экран (`max-width: 92vw`), critical actions (вход, просмотр карточки, toast) не ломаются — это ручная, не автоматизированная проверка |
