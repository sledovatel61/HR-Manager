## 2. Внешние источники (референсы), дата просмотра — 2026-09-02

Для каждого источника: конкретный паттерн/идея → как адаптировано под HR
Manager. Прототипы конкурентов **не копировались буквально** — использовались
только как источник паттернов.

### 2.1 Nielsen Norman Group — принципы дашбордов и визуализации данных
- Обзорная статья по дизайну дашбордов, ссылающаяся на выводы NN/G о
  progressive disclosure (снижение когнитивной нагрузки) и Z-паттерне
  сканирования: https://thedan.design/insights/dashboard-design-principles-best-practices-to-enhance-your-data-analysis/
- NN/G «Data Visualizations for Dashboards»: https://www.nngroup.com/videos/data-visualizations-dashboards/
- **Паттерн:** показывать сводку сверху, детали — по требованию; не более 5–7
  конкурирующих элементов в верхней части экрана.
- **Адаптация:** `HomePage` прототипа ограничен 4 смысловыми блоками
  («Требует внимания», «Ближайшие события», «Моя очередь», «Команда сегодня»
  — последний только для руководителя/админа), а не решёткой из 10+ метрик.

### 2.2 Таблицы с большим объёмом данных
- https://ninjatables.com/searchable-and-sortable-tables/ — рекомендации по
  поиску, сортировке, hover-действиям, ограничению видимых колонок (5–8).
- **Адаптация:** `CandidateTable` показывает 8 значимых колонок, hover
  раскрывает быстрые действия (передача, смена статуса), сортировка — по
  трём ключевым столбцам с понятной кнопкой-заголовком.

### 2.3 Carbon Design System — Empty states
- https://carbondesignsystem.com/patterns/empty-states-pattern/
- **Паттерн:** empty state должен *заменять* таблицу целиком (не показывать
  пустые заголовки колонок и футер) — это упрощает восприятие для
  screen reader и глаз.
- **Адаптация:** `EmptyState`/`StateView` в прототипе рендерятся вместо
  таблицы/канбана целиком, а не поверх пустой структуры.

### 2.4 Attio — модель "views" (Table/Kanban), record sidebar, timeline
- https://attio.com/help/reference/attio-101/attios-data-model/understanding-lists
- https://attio.com/help/reference/attio-101/attios-data-model/define-your-data-model-objects-lists-and-views
- **Паттерн:** одна и та же коллекция записей просматривается как таблица
  или Kanban через явный переключатель вида; карточка записи открывается в
  боковой панели (sidebar/drawer), не как отдельная страница, чтобы не терять
  контекст списка.
- **Адаптация:** `CandidatesPage` реализует переключатель "Таблица/Kanban" в
  заголовке; `CandidateDrawer` открывается сбоку поверх текущего списка.
  Cпецифичная для Attio цветовая айдентика (зелёно-бирюзовая) **не
  копировалась** — HR Manager использует нейтральный indigo-акцент (см.
  `CONCEPTS.md`).

### 2.5 Command palette (Linear/Superhuman/общие гайды 2026 года)
- https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/ —
  правила: палитра доступна отовсюду по одному шорткату, объединяет
  навигацию и действия в одном месте, группировка команд, "лишний" последний
  пункт намекает на прокрутку.
- https://www.techinterview.org/post/3233475212/build-command-palette-cmd-k/
  — техническая архитектура: реестр команд, ARIA combobox (input держит DOM
  focus, `aria-activedescendant` указывает на активный пункт), Escape
  закрывает и возвращает фокус.
- **Адаптация:** `CommandPalette` в прототипе объединяет навигацию по
  разделам, 2 быстрых действия и поиск по кандидатам в одном списке с
  группировкой; реализован по ARIA combobox-паттерну (см.
  `ACCESSIBILITY.md`), открывается по Ctrl/Cmd+K из любого экрана.

### 2.6 WAI-ARIA Authoring Practices — Dialog (Modal)
- https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/ (раздел
  3.9 Dialog Modal) и обзорная статья
  https://www.uxpin.com/studio/blog/keyboard-navigation-patterns-complex-widgets/
- **Паттерн:** при открытии диалога фокус переходит внутрь; Tab/Shift+Tab
  зациклены внутри диалога; Escape закрывает; после закрытия фокус
  возвращается на элемент, открывший диалог (кроме случая, когда этот
  элемент исчез — тогда фокус переходит в логичное следующее место).
- **Адаптация:** общий хук `useFocusTrap` (`design-prototype/src/components/ui/useFocusTrap.ts`)
  реализует именно эту последовательность и используется в `Modal`, `Drawer`
  и `CommandPalette`.

### 2.7 WCAG 2.2 — новые критерии
- Сводка новых критериев 2.2: https://www.wcag22aa.org/new-criteria/ и
  https://www.audioeye.com/post/wcag-22/
- **Факт:** WCAG 2.2 (октябрь 2023) добавляет 9 критериев, среди них на
  уровне AA — Focus Not Obscured (Minimum) 2.4.11, Dragging Movements 2.5.7,
  Target Size (Minimum) 2.5.8 (≥24×24px), Consistent Help 3.2.6 (A),
  Redundant Entry 3.3.7 (A), Accessible Authentication (Minimum) 3.3.8 (AA).
- **Адаптация:** Kanban drag-and-drop дополнен keyboard-alternative (select
  "переместить на этап") — прямое соответствие 2.5.7; интерактивные
  элементы (`IconButton`, чипы) спроектированы с минимальной областью
  клика ≥28–32px — соответствие духу 2.5.8 (полный аудит см.
  `ACCESSIBILITY.md`, статус "требует отдельного аудита" для точных
  измерений в браузере).

### 2.8 Deque / adacompliancepros — практика фокус-менеджмента в модалках
- https://www.adacompliancepros.com/blog/accessible-modal-dialog
- **Паттерн:** после закрытия диалога фокус не должен "падать" на body или
  в начало страницы — только на логичный следующий элемент.
- **Адаптация:** `useFocusTrap` явно хранит `previouslyFocused` и
  восстанавливает фокус на него при размонтировании/закрытии.

## 3. Что сознательно НЕ копировалось

- Точная цветовая идентичность конкретных продуктов (например, характерный
  зелёно-бирюзовый Attio, фирменный фиолетовый Linear) — HR Manager получил
  собственную нейтральную indigo-палитру (см. `CONCEPTS.md`/`DESIGN_SYSTEM.md`).
- Логотипы, иконные наборы, шрифты и любые проприетарные ассеты сторонних
  продуктов — все иконки в прототипе оригинальные inline SVG
  (`design-prototype/src/icons/Icon.tsx`), созданные с нуля для этого проекта.
- Закрытые (платные/приватные) дизайн-гайды или Figma-файлы — не
  использовались и не скачивались.

## 4. Ограничения исследования

- Исследование проведено веб-поиском и чтением публичных страниц/документации
  без визуального интерактивного тестирования конкурентных продуктов (нет
  доступа к живым аккаунтам Attio/Ashby/Lever в песочнице).
- WCAG-соответствие в этом документе основано на **письменных критериях**, а
  не на прогоне автоматических инструментов (axe, Lighthouse) внутри
  headless-браузера — в песочнице такой браузер недоступен. См. разделение
  «проверено / проверено частично / требует отдельного аудита» в
  `ACCESSIBILITY.md`.
