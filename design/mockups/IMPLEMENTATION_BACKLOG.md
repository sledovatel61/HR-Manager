# Что обязательно учесть при внедрении (заметки заказчика)

Файл-памятка: требования, которые прозвучали устно при обсуждении мокапов
(сессия выбора палитры, агент, готовивший мокапы). Не удалять до внедрения.

**Происхождение подтверждено:** оба пункта — прямая речь заказчика в диалоге
с агентом, который делал мокапы, а не выдумка. Ревьюер
(`design-review/BENTO_SHOWCASE_REVIEW.md` §5) не смог это подтвердить, потому
что в его диалоге этих слов не было — это ожидаемо, диалоги разные.

## 1. Фильтр «Должность» на экране «Кандидаты»

**Суть.** В списке кандидатов нужен отдельный фильтр по должности. Если HR выбирает
«монтажник», в таблице и в воронке должны остаться только анкеты монтажников.

**Где в продакшен-коде**

| Что | Файл | Куда |
| --- | --- | --- |
| Поле фильтра в тулбаре | `frontend/src/features/candidates/CandidatesListPage.tsx` | блок `.list-toolbar-row.list-filters` (строки ~119–160) — рядом с фильтрами «Этап», «Источник», «Ответственный», «Сортировка»; использовать общий хелпер `SelectInput` (строка ~357) |
| Логика фильтрации | `frontend/src/features/candidates/useCandidatesList.ts` | добавить `position` в состояние фильтров и в выборку |
| Канбан | `frontend/src/features/candidates/KanbanPage.tsx` | тот же фильтр применяется к колонкам воронки |
| Стили | `frontend/src/features/candidates/candidates.css` | селект по ширине как у «Источника» |

**Данные (исправлено).** Раньше здесь было написано «список брать из уже
существующего справочника вакансий» — **такого справочника в проекте нет**
(`grep -rln 'vacanc' frontend/src` → 0 совпадений). Должность кандидата —
свободный текст (`CandidateFormModal.tsx`: `position: string`).

**Выбран вариант (а) из `prompts/BENTO_ARCTIC_IMPLEMENTATION_PROMPT.md` §7.1:**
фильтр по свободному тексту `position`, без нового справочника. Вариант (б)
(завести минимальный справочник должностей) вынесен в отдельную задачу.

**Поведение.** Фильтр Combine-ится с остальными (этап + источник + ответственный +
должность), сбрасывается кнопкой «Сбросить», значение видно в «активных чипах»
над таблицей. Пустое значение = «Все должности».

## 2. Сохранить и усилить вкладку «Моя очередь» (сводка)

Заказчик прямо отметил: «мне понравилась главная вкладка со сводками, очень удобно,
у меня в приложении этого не было». При внедрении:

- экран «Моя очередь» (`#/queue` в мокапе) — персональный дашборд HR: задачи на
  сегодня, просроченные, ближайшие события, KPI недели, мини-воронка;
- `frontend/src/app-shell/Workspace.tsx` уже маршрутизирует HR-пользователя в секцию
  `queue` (строки ~76–79, маппинг секций ~212) — секцию нужно наполнить
  реальными данными, а не держать заглушкой;
-метрики: «мои задачи», «просрочено», «выходы на неделе», «новые отклики».

**Статус:** сделано (коммит `b335f29`). Фильтрация — на сервере
(`GET /candidates?position=`), иначе при 20 строках на странице «останутся
только монтажники» выполнялось бы лишь в пределах текущей страницы.

## 3. Выбор палитры (решение принято)

На выбор 4 варианта одного макета Bento Showcase:

- `bento-showcase.html` — оригинал, фиолетовый акцент `#6d5ef8`
- `bento-emerald.html` — «Изумруд», акцент `#047857`
- `bento-coral.html` — «Коралл», акцент `#be123c`
- `bento-arctic.html` — «Лазурь / Arctic blue», акцент `#0b6bcb`

Все четыре — один и тот же HTML/JS, отличается только блок CSS-токенов
(`:root` и `[data-theme="dark"]`): акцент, нейтральная шкала, тень, mesh-пятна,
градиенты аватаров и категориальные цвета графиков (`--cat-*`).
Статусные цвета (успех/предупреждение/опасность/инфо) во всех палитрах одинаковые —
они семантические и не зависят от акцента.

**Выбрана «Лазурь»** (`bento-arctic.html`, акцент `#0b6bcb`).

**Статус:** токены перенесены в `frontend/src/design-system/tokens.css`,
материал направления — в `design-system/components/bentoSurface.css`. План
внедрения: `IMPLEMENTATION_PLAN.md`.

**Статус:** сделано (коммит `efcec0b`). Экран «Моя очередь» открывается над
рабочим списком кандидатов; данные только из существующих endpoint'ов, новых
полей в API не заведено.
