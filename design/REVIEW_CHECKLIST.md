# REVIEW_CHECKLIST.md — чек-лист для владельца проекта

## Визуальная целостность
- [ ] Один акцентный цвет используется последовательно на всех экранах (indigo)
- [ ] Статусы кандидатов визуально согласованы между таблицей, Kanban и карточкой
- [ ] Нет случайных несогласованных радиусов/теней вне описанных в `DESIGN_SYSTEM.md`
- [ ] Тёмная тема (переключатель в topbar/Settings) не ломает читаемость ни на одном экране

## UX
- [ ] Все 18 обязательных user flow из `PERSONAS_AND_FLOWS.md` проходимы кликом
- [ ] Command Palette (Ctrl/Cmd+K) открывается из любого экрана и находит и разделы, и кандидатов
- [ ] Переключение Таблица/Kanban не сбрасывает активные фильтры
- [ ] Передача кандидата требует явного подтверждения (нельзя передать в один клик)
- [ ] Пустые/загрузочные/ошибочные состояния не выглядят как "сломанный экран"

## Accessibility
- [ ] Полная клавиатурная навигация по каждому экрану (Tab, Shift+Tab, Enter, Escape)
- [ ] Фокус виден всегда при клавиатурной навигации (`:focus-visible`)
- [ ] Ни один статус/состояние не передаётся только цветом
- [ ] Escape закрывает любую открытую модалку/drawer/палитру и возвращает фокус
- [ ] Прогнан независимый аудит (axe/Lighthouse/ручной screen-reader тест) — см. `ACCESSIBILITY.md`, раздел "Требует отдельного аудита", это **не выполнено** в рамках дизайн-этапа и должно быть сделано отдельно перед продакшен-релизом

## Responsive (desktop-приоритет)
- [ ] Проверено на 1440×900, 1280×800, 1024×768 (см. `INFORMATION_ARCHITECTURE.md` §12)
- [ ] Таблицы и Kanban корректно скроллятся горизонтально на узких экранах
- [ ] Критические действия (вход, просмотр карточки, подтверждения) не ломаются на мобильной ширине, даже если layout не оптимален

## Производительность
- [ ] `npm run build` укладывается в разумный размер бандла (см. отчёт: ≈226 KB JS до gzip, ≈73 KB после)
- [ ] Нет тяжёлых анимаций, блокирующих взаимодействие (`prefers-reduced-motion` уважается)
- [ ] Список из 32 моковых кандидатов не создаёт заметных лагов при фильтрации/сортировке (не тестировалось при бóльших объёмах — для сотен/тысяч записей потребуется виртуализация таблицы, см. `IMPLEMENTATION_GUIDE.md`)

## Отсутствие реальных данных
- [ ] Все ФИО, телефоны, email, компании — синтетические (домены только example.com/.org/.net)
- [ ] Нет реальных URL аватаров — только инициалы
- [ ] Нет секретов, токенов, реальных паролей в коде или комментариях

## Отсутствие внешних runtime-запросов
- [ ] Нет обращений к внешним CDN (шрифты — системный стек, иконки — inline SVG)
- [ ] `vite.config.ts` прототипа не проксирует и не обращается к реальному backend
- [ ] Приложение работает при полном отключении сети (после первой загрузки статики)

## Отсутствие конфликта с production frontend
- [ ] `frontend/src` не изменён (проверить `git diff --stat -- frontend/src`)
- [ ] Backend, миграции, `.github/workflows`, Docker Compose не изменены
- [ ] Прототип живёт в изолированном каталоге `design-prototype/` с собственным `package.json`, не влияет на `frontend/package.json`
