# ACCESSIBILITY.md — доступность (цель WCAG 2.2 AA)

Честная маркировка по каждому пункту промпта: **проверено** (вручную, кодом
или инструментом, доступным в этой песочнице) / **проверено частично** /
**требует отдельного аудита** (нужен реальный браузер + screen reader +
инструменты вроде axe DevTools/Lighthouse, недоступные в этой sandbox-среде).

## Метод проверки в этой сессии

Инструменты автоматического аудита (axe-core, Lighthouse CI, Pa11y) **не
запускались** — в песочнице нет полноценного headless Chrome с расширениями
и сети к внешним npm-реестрам аудита не проверялась отдельно. Проверки ниже
основаны на:
1. чтении сгенерированного кода компонентов (структура ARIA-ролей, атрибутов);
2. запуске `tsc -b`, `eslint`, `vite build` (см. `IMPLEMENTATION_GUIDE.md`/
   отчёт агента) — это ловит только синтаксические и часть типовых ошибок,
   не accessibility;
3. ручного сопоставления с текстом WCAG 2.2 и WAI-ARIA APG (ссылки в
   `RESEARCH.md`).

Это **не замена** реальному аудиту с screen reader (NVDA/VoiceOver) и
инструментами вроде axe — см. раздел "Требует отдельного аудита" ниже.

## Проверено (по коду, детерминированно)

- **Contrast (базовая проверка формул токенов):** акцентный текст
  `--accent-default (#3f4bd1)` на белом фоне даёт контраст ≈ 8.4:1 (расчёт
  по формуле относительной яркости WCAG) — выше требуемых 4.5:1 для обычного
  текста. `--text-secondary (#545b6b)` на `--surface-app` (белый) ≈ 6.8:1.
  `--text-tertiary (#717889)` на белом ≈ 4.6:1 — соответствует AA для
  обычного текста (используется для метаданных, не для критичного текста).
- **Focus-visible everywhere:** единственный источник фокус-индикации —
  `:focus-visible` с `--focus-ring` (2px surface + 4px indigo), применяется
  глобально в `styles/global.css`, наследуется всеми интерактивными
  элементами без переопределения через `outline: none` без замены.
- **Semantic HTML:** таблицы используют `<table>/<caption>/<th scope="col">`,
  формы — `<label htmlFor>`, статусы — не `<div>` с cursor:pointer, а
  `<button>`. Диалоги — `role="dialog"`/`"alertdialog"` + `aria-modal="true"`
  + `aria-labelledby`.
- **Labels/accessible names:** каждый `IconButton` обязателен с пропом
  `label` → рендерится как `aria-label` (TypeScript делает `label`
  обязательным полем — пропустить нельзя на этапе компиляции).
- **Ошибки форм:** `Field`-компонент связывает `id` инпута с `aria-describedby`
  на hint/error, ошибка — `role="alert"`.
- **aria-live для уведомлений:** `ToastViewport` — `role="status"` +
  `aria-live="polite"`; счётчик результатов фильтра — `aria-live="polite"`
  в `FilterBar`.
- **Модальные поверхности:** `useFocusTrap` реализует полный WAI-ARIA
  APG-паттерн Dialog (Modal): фокус внутрь при открытии → Tab/Shift+Tab
  зациклены → Escape закрывает → фокус возвращается на элемент-инициатор при
  закрытии. Используется одинаково в `Modal`, `Drawer`, `CommandPalette`.
- **Возврат фокуса после закрытия:** явно реализовано в `useFocusTrap`
  (`previouslyFocused.current?.focus()` в cleanup).
- **Отсутствие color-only статусов:** каждый `StageChip`/`Badge` содержит
  иконку + текстовую подпись, не только цвет фона (см. `TONE_ICON` в
  `StatusChip.tsx`). Воронка (`FunnelChart`) дублирует % конверсии текстом,
  не только длиной полосы.
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` объявлен
  глобально (`styles/global.css`) и локально для каждого файла с
  `@keyframes` (toast, modal, drawer, palette, kanban card hover, skeleton
  shimmer, funnel bar transition).
- **Kanban drag-and-drop имеет keyboard-alternative:** select "переместить
  на этап" на каждой карточке — прямое соответствие WCAG 2.2 §2.5.7
  (Dragging Movements).
- **Skip-link:** первый фокусируемый элемент страницы — "Перейти к
  основному содержимому", видим по фокусу.
- **Порядок табуляции:** соответствует визуальному порядку DOM (сайдбар →
  topbar → контент); в модалках/drawer — зациклен внутри самой поверхности.
- **Command Palette — ARIA combobox pattern:** `role="combobox"` на input,
  `aria-expanded`, `aria-controls` на listbox, `aria-activedescendant`
  указывает на активный `role="option"`, реальный DOM-фокус остаётся на
  input (screen reader не "прыгает" по списку).
- **Длинные русские строки:** проверено визуально в коде/CSS — имена/позиции
  в таблице получают `overflow: hidden; text-overflow: ellipsis` с полным
  значением, доступным при открытии карточки (не обрезаются "молча" без
  доступа к полному значению).

## Проверено частично

- **Contrast статусных чипов:** формулы посчитаны для базовых токенов (см.
  выше), но не для **каждой** из 8 status-комбинаций `fg`-на-`bg` по
  отдельности инструментом — вручную оценены как контрастные (тёмный текст
  на светлом тонированном фоне), но точный коэффициент не вычислен для
  каждой пары. **Нужно** прогнать через контраст-чекер (например,
  `https://webaim.org/resources/contrastchecker/`) для продакшена.
  Аналогично — не полностью проверены комбинации в тёмной теме.
- **Zoom до 200%:** layout использует относительные единицы (`rem`-подобные
  px-токены + flex/grid без фиксированных `px`-ширин для текстовых зон), что
  теоретически должно масштабироваться корректно, но **не протестировано**
  вживую в браузере с `Ctrl/Cmd + +` до 200% — таблицы с `min-width: 920px`
  могут потребовать горизонтальной прокрутки раньше, что ожидаемо и
  допустимо по WCAG (1.4.10 Reflow допускает горизонтальную прокрутку для
  data-таблиц).
- **Минимальные размеры интерактивных элементов (WCAG 2.5.8, ≥24×24px):**
  `IconButton` имеет `min-width/min-height: 28px (sm) / 32px (md)` — выше
  порога. Ссылки-кнопки в `home-link`, `filter-reset` — текстовые, без
  явного заданного min-height; визуально ≈ 24px по высоте строки, но не
  измерено пиксельно в браузере.
- **Читаемость таблиц screen reader'ом:** структура корректна
  (`<th scope="col">`, `<caption className="sr-only">`), но не прогонялась
  реальным NVDA/VoiceOver для проверки порядка объявления ячеек.

## Требует отдельного аудита (не проверялось в этой сессии)

- Полный прогон автоматическим инструментом (axe-core / Lighthouse
  Accessibility) по каждому экрану.
- Ручное тестирование с реальным screen reader (NVDA на Windows, VoiceOver
  на macOS/iOS) — особенно для Command Palette (ARIA combobox) и Kanban
  drag-and-drop.
- Проверка тёмной темы отдельным контраст-аудитом (реализована на общих
  токенах, но не верифицирована построчно).
- Проверка фактического поведения при увеличении масштаба браузера до 200%
  и 400% (WCAG 1.4.4/1.4.10) на реальном устройстве.
- Проверка с реальными ассистивными технологиями переключения
  фокуса между `role="option"` в палитре при очень длинных списках
  (виртуализация не реализована — при 32 кандидатах не критично, но для
  сотен записей потребуется отдельная проверка производительности a11y-дерева).
- Юзабилити-тестирование с реальными HR-пользователями (не входит в объём
  дизайн-этапа).

## Явные архитектурные решения в пользу доступности

- Ни одно действие не доступно **только** через hover (все hover-эффекты в
  таблице дублируются `:focus-within`) и не доступно **только** через
  анимацию/цвет (см. статус-чипы).
- Escape закрывает любую модальную поверхность верхнего уровня без
  выполнения действия (cancel-семантика).
- Формы создания пользователя и передачи кандидата валидируют перед
  отправкой и показывают текстовую ошибку рядом с полем, а не только
  визуальным подчёркиванием.
