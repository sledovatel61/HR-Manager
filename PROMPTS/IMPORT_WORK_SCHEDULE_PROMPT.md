# Задача: импорт графика выхода из Excel в кандидатов и «График выхода»

Репозиторий: `https://github.com/sledovatel61/HR-Manager`  
Рабочая ветка: `arena/<id>-import-work-schedule`, один PR в актуальный `main`.  
Независимое ревью будет выполнено отдельно; не смешивать эту работу с другими PR.

## Контекст

В каталоге владельца есть реальный исходный файл:

`C:\Users\User\Documents\HR\HR Manager Desktop\LLM\30.09.2026\График приемов .xlsx`

Это рабочий Excel-график выхода сотрудников. В нём есть группировка по датам и
строки с ФИО, временем, организацией, отделом, должностью, сменой и комментарием.
Иногда встречаются служебные строки без кандидата. Папку `Скрины проблем
программы` не открывать и не изменять.

Цель: Мария выбирает Excel-файл в интерфейсе, запускает импорт и получает связные
данные сразу в двух местах:

1. реальные люди создаются или сопоставляются с кандидатами в картотеке;
2. у этих кандидатов заполняются поля выхода на работу и они появляются в разделе
   «График выхода»;
3. служебные строки попадают в отдельные записи графика, если такой тип уже
   предусмотрен реализацией Phase 18.

Не делать отдельную параллельную модель графика. Сначала изучить актуальный
`main`: если Phase 18 уже смержен, переиспользовать его модели, API, права,
аудит и экспорт. Если Phase 18 отсутствует, сначала реализовать необходимый
график по `prompts/PHASE_18_WORK_SCHEDULE_PROMPT.md` в этом же PR, затем импорт.
Не оставлять импорт, зависящий от несуществующего раздела. Если график уже делает
другой агент, согласовать базовую ветку с оркестратором до изменений общих моделей.

Локальный Windows-путь недоступен удалённому агенту Арены автоматически. Владелец
прикладывает XLSX к заданию приватно; если вложение недоступно, сообщить об этом,
не утверждать, что реальный формат проверен, и не заменять приёмку выдуманным файлом.

## Требования

### Интерфейс

- Добавить понятную русскую кнопку/раздел «Импорт графика из Excel» рядом с
  «Графиком выхода» или в подходящем месте по существующей навигации.
- Файл выбирается стандартным диалогом Windows через `<input type=file>`; путь к
  файлу не отправлять и не хранить, отправлять только содержимое multipart-запросом.
- Перед записью показать preview: число строк, распознанные даты, кандидаты,
  новые/обновляемые/сомнительные строки и ошибки.
- Для неоднозначных строк дать понятный выбор: пропустить, сопоставить с найденным
  кандидатом или создать нового. Не создавать дубликаты молча.
- Импорт должен иметь режим «проверить без сохранения» либо эквивалентный preview,
  а затем явную кнопку подтверждения.
- После импорта показать итог: создано, сопоставлено, обновлено, создано
  служебных записей, пропущено, ошибок. Дать возможность скачать/скопировать
  отчёт об ошибках.

### Разбор файла

- Исследовать фактическую структуру указанного XLSX: объединённые ячейки,
  заголовки дней, пустые строки, форматы дат/времени и служебные строки.
- Не зашивать номера строк так, чтобы импорт работал только на одном файле.
  Распознавать заголовки и дату блока устойчиво, с понятной ошибкой при неизвестном
  формате.
- Поддержать русские даты Excel, даты-числа Excel, время Excel и текстовое время.
- Поля строки: ФИО, время, организация, отдел, должность, смена, комментарий.
  Существующие поля кандидата использовать повторно, не создавать дублирующие
  `position`/`start_*` поля.
- Незнакомые строки не терять: показать их в отчёте импорта с причиной.
- Ограничить размер и количество строк файла, проверять MIME/расширение и не
  принимать произвольные архивы или макросы.

### Сопоставление кандидатов и целостность

- Предлагать совпадения только среди доступных кандидатов. Даже одно совпадение
  ФИО не гарантирует идентичность человека: без дополнительного надёжного признака
  сопоставление требует подтверждения. Не раскрывать наличие чужих кандидатов.
- При отсутствии совпадения предложить создание кандидата только с теми данными,
  которые есть в таблице; не выдумывать телефон, email или другие ПДн.
- Не менять ответственного HR без явного правила текущей модели доступа.
- Импорт одной подтверждённой пачки атомарен: ошибка не должна оставить половину
  кандидатов и половину строк графика. При больших файлах можно использовать
  безопасную поэтапную обработку, но результат каждого шага должен быть повторяемым.
- Повторный импорт того же файла не должен создавать дубликаты. Нужен устойчивый
  ключ/идемпотентность и тест на повторный импорт.
- Все изменения провести через существующий аудит без помещения полного Excel,
  содержимого строк и лишних ПДн в audit/logs.
- Проверить серверные права: обычный HR импортирует только доступных ему
  кандидатов, администратор/разрешённая роль — по действующей матрице.

### Безопасность

- XLSX не хранить как загруженный файл после обработки, если это не требуется
  принятой политикой; временные данные удалить после завершения.
- Не выполнять макросы, формулы, ссылки, Python/SQL/Jinja и HTML из таблицы.
- Не логировать ФИО, телефоны, email и полное содержимое строк.
- Защититься от формульной инъекции в отчёте/экспорте.

## Тесты обязательны

- Backend unit-тесты разбора реальных вариантов: даты-блоки, объединённые ячейки,
  пустые строки, время, служебные строки, ошибки формата.
- Backend PostgreSQL integration: preview без записи, подтверждённый импорт,
  повторный импорт без дублей, неоднозначное ФИО, атомарный rollback, права и аудит.
- Frontend Vitest: выбор файла, preview, подтверждение, предупреждение о дублях,
  итог и отчёт ошибок.
- Не коммитить реальный Excel и не коммитить реальные ФИО/ПДн. Создать обезличенный
  fixture, сохранив структуру исходного файла.
- Полный существующий CI и migration checks должны остаться зелёными.

## Ограничения и отчёт

- Не трогать `installer/`, `infra/windows/` и папку `Скрины проблем программы`.
- Не ослаблять существующие тесты, не делать tag/Release и production signing.
- В PR коротко указать: как распознан реальный формат, что импортируется,
  как предотвращены дубли, какие тесты прошли и что проверить руками.
