# МЕГАПРОМПТ: редизайн HR‑Manager (HTML‑мокапы для выбора направления)

> ОДИН и ТОТ же промпт выдаётся трём независимым агентам. Каждый агент делает СВОЙ
> интерактивный HTML‑мокап, выбирая направление дизайна ДЕТЕРМИНИРОВАННО‑СЛУЧАЙНО
> (см. §4), чтобы три результата гарантированно разошлись. Человек откроет три ссылки,
> потыкает и выберет направление. Победивший макет потом реализуется ОДНИМ PR.

---

## 0. Роль и цель

Ты — senior product designer + frontend‑инженер. Твоя задача — спроектировать и собрать
**кликабельный high‑fidelity HTML‑мокап** нового визуального языка для существующего
внутреннего продукта «HR‑Manager» (ATS/CRM для HR: воронка кандидатов, календарь событий,
график выхода, аналитика, документы, шаблоны, уведомления). Это ТОЛЬКО макет для
демонстрации направления дизайна. Никаких изменений в боевой код не вносится.

Цель макета — «вау»: человек должен открыть ссылку, пощёлкать по экранам/темам и сказать
«хочу так». При этом макет обязан быть **реализуемым одним PR** в текущем стеке, поэтому
каждое визуальное решение ты выражаешь через CSS‑переменные, повторяющие существующую
систему токенов (§3).

## 1. Жёсткие ограничения (нарушение = брак)

1. **Не трогай боевой код.** Только мокап в отдельной папке/отдельном файле. Не правь
   `frontend/src/**`, не ставь зависимости в реальный `package.json`.
2. **Не ломай функционал.** Макет — витрина. Все «данные» — статичные/сгенерированные
   заглушки, выглядящие как реальные.
3. **Один PR реализуемость.** Дизайн обязан раскладываться на: (а) новые значения
   существующих semantic‑токенов, (б) restyle существующих компонентов через их CSS.
   Никаких новых runtime‑зависимостей, никаких внешних веб‑шрифтов в БОЕВОЙ версии
   (в мокапе шрифты с CDN допустимы ТОЛЬКО для превью, но дизайн обязан деградировать до
   системного стека без потери характера — проверяй это переключателем «system fonts»).
4. **Русский язык интерфейса.** Весь текст — на русском, как в продукте.
5. **Доступность:** контраст ≥ WCAG AA, видимый focus‑ring, информация не только цветом.
6. **Производительность превью:** чистые HTML/CSS/JS без сборщиков; анимации на
   transform/opacity; никаких тяжёлых библиотек.

## 2. Что за продукт и какие экраны есть (реальная структура)

Навигация (сайдбар) и экраны, которые существуют в проде:

- **Моя очередь** (inbox) — задачи/заявки, требующие действия.
- **Кандидаты** — таблица соискателей + карточка‑drawer с вкладками: Сообщения, Документы,
  Вложения, Сгенерированные документы, Перемещения; форма создания; дубликаты.
- **Воронка кандидатов** — kanban по этапам (drag‑and‑drop).
- **Календарь** — сетка недели/дня, события (звонок/собеседование/оффер), модалка события.
- **График выхода** — таблица‑календарь выходов + импорт из Excel (wizard).
- **Аналитика** — KPI‑карточки, воронка конверсий, графики по периодам (день/неделя/квартал),
  фильтры (таймзона, HR, источник).
- **Уведомления**, **Напоминания** — ленты с действиями «Выполнено».
- **Списки документов**, **Шаблоны и материалы** (библиотека) — списки, wizard, превью.
- **Удалённые** (корзина), **Настройки** (пользователи, интеграции, обновления).

Текущий вид (для контраста): тёмный графитовый сайдбар + светлый контент, белые скруглённые
карточки, индиго‑акцент, обычные формы и модалки, «generic admin». Скриншоты текущего
состояния лежат в `PROMPTS/skrinshots/` (их МОЖНО смотреть). Нам нужно уйти от «generic admin» к осмысленному,
современному, премиальному виду.

## 3. Существующая система токенов (обязательно прочитать и отразить)

В проде есть `frontend/src/design-system/tokens.css`: компоненты используют ТОЛЬКО
semantic‑переменные, тема переключается подменой значений. Прочитай этот файл и ЗЕРКАЛЬНО
используй те же имена переменных в мокапе, чтобы будущий PR был «подменой токенов»:

- `--surface-canvas/app/raised/sunken/overlay/hover/pressed/selected/disabled/sidebar`
- `--text-primary/secondary/tertiary/disabled/inverse/link/on-accent/sidebar`
- `--border-subtle/default/strong/focus`
- `--accent-default/hover/pressed/subtle/subtle-border`
- `--status-{info,success,warning,danger,neutral,violet,teal,indigo}-{fg,bg,border}`
- `--space-1..10`, `--radius-xs..full`, `--shadow-1..4`, `--text-size-2xs..3xl`,
  `--duration-*/--easing-*`, `--sidebar-width`, `--row-height`, `--control-height-*`.

Также существуют светлая и тёмная темы и режимы плотности `comfortable/compact`.
**В мокапе сделай переключатели: Тема (light/dark) и Плотность (comfortable/compact)** — они
переключают блок `[data-theme]`/`[data-density]`, как в проде.

## 4. Направления дизайна — выбери ОДНО

Сначала прочитай §2–§3. Затем **выбери направление детерминированно‑случайно**: возьми
`hash(идентификатор_твоего_окружения_или_случайное_число) % 6` (или честно брось «кубик») и
возьми направление с этим номером. ОБЯЗАТЕЛЬНО напиши в начале ответа: «Я выбрал направление
№N — <название>» и НЕ подсматривай в другие. Если выпало то же, что у «соседа» — всё равно
трактуй его СВОЕОБРАЗНО (своя палитра в рамках направления).

1. **Calm Precision (Linear/Stripe/Grafana).** Светлый, data‑first. Сайдбар 256px→64px,
   KPI‑полоса 4–6 карточек, 12‑колоночная сетка, skeleton‑лоадеры, табличные цифры,
   сдержанный один акцент, тонкие 1px‑бордеры вместо теней. Без glassmorphism.
   Характер: «инженерная точность, премиальная сдержанность». Референс: Linear, Stripe,
   Vercel, Grafana.
2. **Warm Soft (Attio/Notion).** Тёплый off‑white канвас, tinted‑заголовки секций,
   rounded‑2xl карточки, пастельные статус‑чипы, много воздуха, дружелюбная типографика,
   мягкие hover‑подъёмы. Характер: «уютный, человеческий, современный». Референс: Attio,
   Notion, Height, Plain.
3. **Mission Control (dark‑first).** Глубокий slate/near‑black, светящиеся графики,
   градиентные акценты ТОЛЬКО на KPI‑дельтах и спарклайнах, frosted‑панели лишь для
   overlay/модалок, неоновые статус‑точки. Характер: «операционный центр, вау в темноте».
   Референс: Vercel dark, Raycast, Linear dark, дашборды Caltimes.
4. **Bento Showcase (glassmorphism/bento).** Bento‑grid дашборда, frosted‑glass карточки,
   мягкий свет и градиентные mesh‑пятна на канвасе, крупные числа, плавные spring‑анимации.
   Характер: «витрина, максимальный вау». ВАУ‑элемент обязателен. (Помни: такое стареет
   быстрее — компенсируй читабельностью.) Референс: Apple‑style bento, muz.li‑подборки.
5. **Bold Editorial (neo‑brutalism / editorial).** Сильная типографская шкала, толстые
   2px‑бордеры, плоские насыщенные цвета, крупные заголовки, жёсткие тени‑смещения,
   чёткая сетка. Характер: «смелый, журнальный, запоминающийся». Референс: Gumroad,
   neo‑brutalist‑дашборды.
6. **Duotone Fintech.** Кремовый канвас + один глубокий фирменный цвет (например,
   тёмно‑зелёный или индиго), serif‑display заголовки, editorial‑отступы, тонкие линии,
   аккуратные таблицы. Характер: «дорогой, банковский, редакционный». Референс: Mercury,
   Ramp, Stripe‑press.

## 5. Обязательный состав макета (минимум)

Собери и свяжи навигацией (hash‑роутинг) минимум экраны:
1. **Дашборд/«Моя очередь»** — KPI‑полоса, 1–2 графика, лента задач (главный «вау»‑экран).
2. **Кандидаты** — таблица + открытая карточка‑drawer с вкладками и статус‑чипами.
3. **Воронка** — kanban с колонками этапов и карточками (виден drag‑affordance).
4. **Аналитика** — KPI + воронка конверсий + период‑пресеты.
5. Любая форма/wizard (например, «Новый список документов») — показать стиль форм.

## 6. Обязательные «вау»‑элементы (покажи в мокапе)

- Command palette (Ctrl/Cmd+K) с поиском по кандидатам/экранам.
- Skeleton‑лоадеры и плавное появление контента (stagger).
- Микро‑анимации: hover‑подъём карточек, анимированные счётчики KPI, спарклайны.
- Тост‑уведомления и focus‑ring.
- Переключатели **Темы** и **Плотности** (§3) и **«system fonts»** (§1.3).
- Числа с tabular‑nums; аккуратное выравнивание таблиц.

## 7. Реализм данных

Используй правдоподобные русские данные: ФИО («Иванова Анна», «Баев Константин»), этапы
воронки («Отклик → Звонок → Собеседование → Оффер → Выход»), KPI («Создано кандидатов»,
«Конверсия в собеседование», «Средний срок найма»), даты в формате `ДД.ММ.ГГГГ`. Объёмы —
как в проде (таблица 10–20 строк, kanban 4–6 колонок по 3–6 карточек).

## 8. Доставка (чтобы человек «открыл и потыкал»)

- Собери мокап как статические файлы (index.html + style.css + app.js, шрифты/иконки —
  inline SVG или CDN только для превью).
- Подними статический сервер, привязанный к `0.0.0.0` (например `python3 -m http.server`
  или `npx serve -l 0.0.0.0:PORT`), чтобы платформа дала live‑preview URL.
- Убедись, что превью открывается и кликается; в ответе дай URL и краткую сводку:
  направление №, палитра (hex), ключевые решения, что «вау».

## 9. Вместе с макетом отдайImplementation‑план (для будущего одного PR)

Короткий markdown: (а) таблица «semantic‑токен → новое значение (light/dark)»,
(б) список CSS‑файлов компонентов под restyle, (в) риски/что НЕ меняем (функционал, a11y,
системные шрифты), (г) оценка, влезает ли в один PR. Это ускорит реализацию победителя.
