# Плейсхолдеры шаблонов документов (Phase 16)

Справочник закрытого списка подстановок для версионируемых текстовых шаблонов.
Список — часть контракта: сервер принимает **только** эти токены, любой другой
возвращает 422. Каталог доступен приложению через
`GET /document-templates/placeholders` и показан в интерфейсе раздела
«Шаблоны документов» (кнопки вставки под полем текста).

Синтаксис: `{{ namespace.field }}` — допустимы пробелы внутри фигурных скобок.
Свободный HTML, выражения, Jinja, SQL и Python-код не поддерживаются; значения
никогда не исполняются, а всегда экранируются.

## Разрешённые плейсхолдеры

| Токен | Что подставляет |
| --- | --- |
| `{{ candidate.full_name }}` | ФИО кандидата |
| `{{ candidate.position }}` | Должность из карточки кандидата |
| `{{ candidate.stage }}` | Этап воронки (русское название) |
| `{{ candidate.source }}` | Источник кандидата (русское название) |
| `{{ candidate.phone }}` | Телефон кандидата (или «—») |
| `{{ candidate.email }}` | Email кандидата (или «—») |
| `{{ candidate.created_at }}` | Дата создания карточки (ДД.ММ.ГГГГ) |
| `{{ hr.full_name }}` | ФИО ответственного HR |
| `{{ system.date }}` | Текущая дата (ДД.ММ.ГГГГ) |
| `{{ system.datetime }}` | Текущие дата и время (ДД.ММ.ГГГГ ЧЧ:ММ) |

Правила:

- **Пустое значение.** Если поля нет, вместо него подставляется «—». Пропуск
  токена не изменяет смысл текста, но документ остаётся читаемым.
- **Часовой пояс.** `system.date`/`system.datetime` считаются в часовом поясе
  пользователя, создающего документ (личная настройка уведомлений), а не сервера.
- **Только текущий кандидат.** Документ создаётся для карточки, к которой у
  пользователя есть доступ; идентификатор кандидата не может быть передан
  плейсхолдером.
- **`event.*` не входит в MVP.** События, `event_id` и связь с Event
  намеренно исключены из первого контура.
- **Пароли, токены, сессии и другие секреты недоступны** — их нет в списке, и
  расширение списка требует изменения кода и тестов.

## Что запрещено и почему

| Ввод | Ответ |
| --- | --- |
| Неизвестный токен (`{{ candidate.salary }}`) | 422, текст ошибки перечисляет неизвестные токены |
| Токен без namespace (`{{ salary }}`) | 422 |
| Любая `{` или `}` вне полного совпадения `{{ токен }}` | 422 |
| Управляющие символы (включая NUL) | 422 |
| Пустое или пробельное значение | 422 (у версии должны быть заголовок и текст) |
| Текст длиннее 20 000 символов | 422 |

Точное правило для скобок: парсер ищет полные совпадения шаблона
`{{ имя }}` (пробелы внутри допустимы) и проверяет, что **вне** них в тексте нет
ни одного символа `{` или `}`. Поэтому 422 дают незакрытая `{{`, лишняя `}`,
удвоение `{{{{ … }}}}`, одиночная `{`, а также `{{` без имени. Обычный символ `%`
разрешён: «Оплата: 100 000 ₽ (50%)» — валидный текст шаблона.

## Мини-разметка

В теле шаблона поддерживаются только три конструкции, всё остальное —
обычный текст:

- абзацы (пустая строка между блоками);
- строки списка, начинающиеся с `- ` (рендерятся как `<ul><li>`);
- `**полужирный**` внутри абзаца.

Полужирный применяется к **экранированному** тексту до подстановки значений,
поэтому разметка может прийти только из шаблона: если в ФИО кандидата есть
`**текст**` или `<b>`, в документе появятся сами символы, а не форматирование.
HTML из значений всегда экранируется (`&lt;`, `&amp;`, `&quot;`).

## Область применения шаблона

Область (`scope`) не связана с подстановками, но влияет на то, кому доступен
документ:

- пустой `scope` — шаблон применим к кандидату на любом этапе;
- каноническое значение «все этапы» при создании через API — `null` (сервер
  сохраняет его как `""`); хранимые формы `""` и `all` поддерживаются гейтом для
  совместимости и защитной обработки, но не являются обычным вводом через API;
- конкретный `scope` (значение этапа, например `offer`) должен совпадать с
  текущим этапом кандидата, иначе сервер отвечает 422 при предпросмотре и при
  сохранении документа;
- сообщение об ошибке называет этап шаблона и текущий этап кандидата — без
  персональных данных;
- проверка выполняется на сервере для любой роли, её нельзя обойти прямым
  вызовом API; уже сохранённые документы и их повтор по ключу идемпотентности
  смена этапа кандидата не блокирует.

## Артефакты документа

Из одной версии шаблона получаются два равнозначных текстовых представления:

- **Текст** (`format=txt`) — то, что видно в предпросмотре, без разметки;
- **HTML** (`format=html`) — автономный документ с `<meta charset="utf-8">` и
  экранированными значениями, для открытия в браузере и печати в PDF
  средствами браузера. Серверная генерация PDF/DOCX не поддерживается.

Сохранённый документ — неизменяемый снимок: он хранит текст, HTML, номер и имя
версии, имя шаблона и SHA-256 содержимого на момент создания. Изменение
шаблона, переименование или новая версия снимок не меняют. Файлы не
загружаются и не хранятся; кандидату ничего не отправляется — документ видит
только сотрудник с доступом к карточке.
