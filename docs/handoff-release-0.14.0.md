# Handoff релиза 0.14.0 — пилот для Марии (финальная доводка B1–B6)

Дата: 2026-09-29. База: `main` @ `f3430a9f8afb0e35be45260df19f34559568223e`. Ветка пилота: `arena/01a0ec5f-hr-manager`.

## Что вошло

* **B1–B6** — финальная доводка пилота для одного пользователя (см. таблицу в `CURRENT_STATUS.md`).
* Функциональность продукта (кандидаты, правила, шаблоны и т.п.) **не расширялась** — только установка, ярлыки, диагностика, LAN, обновление и сборка.

## Сборка пилотного релиза

* Workflow `pilot-release` (`workflow_dispatch`, без production-сертификатов, без tag/Release):
  `HR-Manager-Setup-<версия>.exe` + `SHA256SUMS.txt` + `license-issuer-dist.zip` → artifacts.
* Лицензионный ключ: `infra/license/public_key.b64` (коммитить можно) или GitHub variable/secret `HRM_LICENSE_PUBLIC_KEY`. Без ключа сборка падает fail-closed.
* Проверка SHA: `sha256sum -c SHA256SUMS.txt` (пилот, без Authenticode).

## Ярлыки

* Рабочий стол и меню Пуск — **HR Manager** (`-Action open`, окно скрыто).
* Только меню Пуск — **отчёт для разработчика** (`support-bundle`), **перезапуск** (`restart`), **доступ по сети** (`lan-access`).
* Автозапуск: папка автозагрузки пользователя (`{userstartup}\HR Manager` → `-Action start`). Если Docker Desktop запущен — приложение поднимается само после входа.

## Отчёт для разработчика

* `support-bundle` → `HR-Manager-report-<дата>.zip` на рабочем столе.
* Внутри: diagnostics JSON, логи, версии, лицензия (без подписи), health/readiness. Всё через `Redact-HrmText`, без дампа БД, `pilot.env`, паролей, PII.
* Подсказка в UI: раздел «Готовность пилота» + текст diagnostics.

## Доступ по сети

* По умолчанию выключен (`127.0.0.1:8080`). `lan-access -Enable` → `0.0.0.0:8080` + правило Firewall Private/Domain (один UAC), `-Disable` → обратно. Настройка в `StateDir/lan.json`, переживает обновление.
* Ярлык показывает `http://<имя-ПК>:8080` и IP. Loopback-only эндпоинты (`/api/setup/*`) по сети недоступны — nginx теперь `X-Real-IP $remote_addr`, бэкенд `loopback_client_ok` проверяет, тесты покрывают подделку заголовка.
* **Принятый риск пилота:** отсутствие HTTPS в офисной сети (HTTP). Для пилота допустимо, для коммерции потребуется TLS.

## Обновление поверх

* Новый `Setup.exe` поверх старого: `Install-HrmApp` ловит смену `release_sha` и ведёт через `Update-HrmApp` (бэкап → замены → миграции → health-check → откат к `:previous` образам при ошибке). Данные и лицензия сохраняются.
* CI: установка N → данные+лицензия → N+1 поверх → на месте; сломанная N+1 → откат, данные на месте.

## Отложено до коммерческого релиза

* **Authenticode/TSA, покупной сертификат, TIMESTAMP_URL, закреплённые корни, PFX, `sign.ps1 -Mode production`, `publish_channel.py --release-mode production`, `SHA256SUMS` по 7 активам, tag `v*` и GitHub Release** — всё это **не требуется для пилота** и перенесено в этот раздел. SmartScreen обходится инструкцией «Подробнее → Выполнить». Production-пайплайн сохранён и не сломан, просто не используется в пилоте. `pilot-release` не создаёт tag/Release и не требует подпись.
* TLS для LAN — тоже отложено.

## Пилотный Go/No-Go

По чек-листу B1–B6 (см. `CURRENT_STATUS.md` и задачу). Production-чек-лист из `runbook-pilot-release.md` для пилота не применяется в части Authenticode.

## Документы для пилота

* `docs/MARIA_GUIDE.md` — простыми словами: Docker Desktop, SmartScreen, установка, первый вход, лицензия, доступ коллеге, отчёт, обновление, «не открывается».
* `docs/OWNER_QUICKSTART.md` — для владельца: скачать artifact → `run-gui.bat` → ключи → куда положить публичный ключ → выпустить лицензию → продление/лимит 2.
* `docs/runbook-pilot-release.md` — обновлён: Authenticode в «отложено», пилотный Go/No-Go по B1–B6.

## Что проверить руками на реальной Windows (до 10 пунктов)

1. Чистая установка Setup.exe → ярлыки на месте, перезагрузка → автозапуск или клик «HR Manager» → открывается `http://127.0.0.1:8080`.
2. SmartScreen → Подробнее → Выполнить — установка проходит.
3. Загрузка лицензии `.hrmlicense` → статус valid, лимит/ срок видны.
4. Ярлык «отчёт для разработчика» → zip на рабочем столе, внутри нет секретов/PII.
5. `lan-access -Enable` → коллега открывает `http://<имя>:8080`, `/setup/owner/claim` по сети → 403/404 (недоступно), подделка `X-Real-IP` не проходит.
6. Лимит 1 — второго пользователя создать нельзя, лимит 2 — можно.
7. Обновление: установить 0.14.0 → создать кандидата + лицензию → поставить 0.14.1 поверх → данные и лицензия на месте.
8. Сломанная миграция (искусственно) → откат, данные на месте, версия прежняя.
9. `SHA256SUMS.txt` совпадает (`sha256sum -c`).
10. `license-issuer-dist.zip` распаковывается, `run-gui.bat` открывает окно без системного Python.

## Ограничения

* Не запускать production signing, не создавать tag/Release.
* Не коммитить приватные ключи, `*.hrmlicense`, `pilot.env`.
* Существующие тесты не ослаблены, CI 7/7 + новые — зелёные на финальном SHA PR.
