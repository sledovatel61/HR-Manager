# Быстрый старт владельца — выдача лицензий HR Manager (пилот)

Это короткая инструкция для владельца. Никакого программирования, только клики мышью.

## 1. Где взять программу для выдачи лицензий

1. Откройте GitHub → ваш репозиторий `HR-Manager` → вкладка **Actions** → выберите последний успешный прогон `CI` (зелёная галочка).
2. Прокрутите вниз до **Artifacts** → скачайте `license-issuer-owner` (внутри `license-issuer-dist.zip`).
   *Альтернатива для пилота:* запустите workflow `Pilot release` → скачайте `pilot-release-<версия>` — внутри тоже есть `license-issuer-dist.zip`.*
3. Распакуйте zip на свой Windows-ПК (например, в `C:\HR-License\`). Интернет и установка Python **не нужны** — всё внутри.

## 2. Первый запуск — создать ключи (один раз)

1. В папке `license-issuer` дважды кликните `run-gui.bat`.
   * Откроется окно «License Issuer». Если не открывается — попробуйте `run-html.bat` (откроется браузер на `http://127.0.0.1:8765`).
2. Нажмите кнопку **«Создать ключи» / Generate keypair**.
   * Появятся два ключа:
     * **Приватный** (`private_key.hex`, 64 символа) — **СЕКРЕТ**. Сохраните в надёжном месте (папка VeraCrypt/BitLocker, зашифрованная флешка, менеджер паролей). Сделайте резервную копию! Этот файл **никогда** не отправляется Марии и не попадает в Git.
     * **Публичный** (`public_key.b64`, 44 символа, выглядит как `CFC5gRcH...`) — откройте, скопируйте.
3. Куда положить публичный ключ (выберите **один** способ):
   * **Способ А — в репозиторий (для пилота):** скопируйте содержимое в файл `infra/license/public_key.b64` в репозитории и сделайте commit. Файл коммитить можно — открытый ключ не секрет. После этого любой пилотный `Setup.exe` будет содержать ваш ключ.
   * **Способ B — в GitHub variable/secret (без коммита):** зайдите GitHub → Settings → Variables/Actions → New variable → имя `HRM_LICENSE_PUBLIC_KEY` → вставьте 44 символа → Save. При сборке `Pilot release` workflow подхватит ключ из переменной (если файла нет). Для секрета — то же, но в Secrets.
   > Если ключа нет ни в файле, ни в переменной — сборка пилотного установщика **упадёт с понятной ошибкой**, а не соберёт нерабочий exe. Это защита (fail-closed).

## 3. Выпустить лицензию для Марии

1. Снова откройте `run-gui.bat` (или `run-html.bat`).
2. Заполните поля:
   * **Имя клиента** — например, `Пилот Марии` или `ООО Пилот — Мария`.
   * **Действует до** — дата `YYYY-MM-DD`, например `2026-12-31` (действует включительно до конца дня по UTC).
   * **Лимит активных пользователей** — например `5` (включает саму Марию).
   * Нажмите **«Выпустить лицензию» / Issue**.
3. Скачайте файл `*.hrmlicense` (JSON). Отправьте его Марии по защищённому каналу (email, мессенджер, флешка). Не переименовывайте внутри — подпись привязана к содержимому.

## 4. Продление срока

Когда срок подходит к концу, Мария увидит баннер. Выпустите новую лицензию:

* Откройте issuer → вставьте тот же **приватный ключ** (кнопка «Загрузить private_key.hex»),
* Укажите ту же или новую дату `expires_at` → новый лимит (если нужно) → Issue → отправьте новый файл.
* Мария в HR Manager зайдёт как администратор → раздел **Лицензия** → **Загрузить** новый файл. Данные и пользователи сохранятся, новая лицензия сразу станет активной.

## 5. Добавить второго HR (доступ по сети)

По умолчанию в пилоте один ПК Марии — это и сервер, и администратор. Второй HR работает **со своего ПК по локальной сети через браузер**, ничего не устанавливая.

1. Сначала увеличьте лимит, если был `1`:
   * Выпустите лицензию с `max_active_users = 2` (или больше) как в п.4 и отправьте Марии.
   * Мария загрузит её — лимит сразу станет 2.
2. На ПК Марии включите доступ по сети:
   * Меню «Пуск» → **HR Manager — доступ по сети** → нажмите **Включить** (или в PowerShell: `hr-manager.ps1 -Action lan-access -Enable` — один запрос UAC для Firewall, только для сетей Private/Domain).
   * Ярлык покажет адреса вида `http://MARIYA-PC:8080` и `http://192.168.1.15:8080` — дайте один из них коллеге.
3. Коллега открывает этот адрес в браузере — логинится своим пользователем (его создаёт Мария в разделе Пользователи, лимит проверяется сервером).
4. Проверка лимита: при `max_active_users = 1` второго активного пользователя создать нельзя (ошибка), при `2` — можно.

## 6. Важно про безопасность

* Приватный ключ **никогда** не попадает в Git, установщик, артефакты, логи, диагностику.
* В приложении только открытый ключ `public_key.b64`.
* Если потеряете приватный ключ — выпустить новую лицензию старым ключом не получится, придётся сгенерировать новую пару и пересобрать Setup.exe с новым публичным ключом.
* Отсутствие HTTPS в офисной сети — **принятый риск пилота**, трафик внутри офиса не шифруется. Для пилота допустимо, для коммерческого релиза будет TLS.

## 7. Что проверить после выпуска

* Откройте `*.hrmlicense` в блокноте — это читаемый JSON, подпись — 128 hex.
* Проверьте кнопкой **Verify** в issuer — должна сказать «подпись верна».
* Спросите Марию скриншот раздела Лицензия — там видны срок и лимит (без подписи).

Если что-то не получается — попросите Марию прислать архив «Отчёт для разработчика» (ярлык на её рабочем столе) и перешлите разработчику.
