# Отчёт: переработка «Шаблонов документов» в библиотеку и панель быстрого доступа

Ветка: `arena/01a0f324-hr-manager` (одна работа, отдельный PR в `main`).
Задача: `PROMPTS/HR_TEMPLATE_LIBRARY_REWORK_PROMPT.md`.

## Что сделано (кратко)

- Раздел вынесен из «Настроек» в основное меню («Шаблоны и материалы», иконка
  «книга») для всех ролей, которым он доступен; старый deep-link `#/templates`
  открывает новый экран. Права на сервере не менялись.
- Главный экран — **Библиотека HR**: заголовок с пояснением, заметный поиск,
  фильтры-категории («Все», Собеседование, Документы кандидата, Звонки и
  сообщения, Онбординг, Памятки HR, Вопросники по должностям) со счётчиками,
  карточки (название, назначение в одну строку, категория, формат, область
  применения, «Открыть»), «Недавно открытые» (localStorage, только id),
  skeleton/error/empty состояния, keyboard/focus-visible/aria, узкое окно.
- Экран просмотра — read-only: заголовок, версия и дата публикации без UUID,
  безопасный серверный рендер (те же экранирующие конвейеры, что и у
  генерируемых документов), «Распечатать» (только документ), «Скачать копию»
  (HTML/TXT), «В новом окне» — все через авторизованные endpoint'ы приложения;
  материалы с подстановками объясняются человеческим текстом и показываются с
  обезличенными демо-значениями вместо `{{ … }}`.
- Встроенный каталог из **10 обезличенных материалов** (список в
  `docs/library.md`), создаётся на чистой установке, идемпотентен по
  `seed_key`, никогда не перезаписывает правки владельца.
- «Управление материалами» — отдельный режим для admin/`document_lists_manage`:
  создание, импорт из файла (с категорией и назначением), версии, публикация,
  архив, переименование, плейсхолдеры. После импорта — предпросмотр черновика
  до публикации. Повторный импорт того же материала даёт явный выбор:
  новая версия существующего / отдельный материал / отмена (409 + диалог).
- Карточка кандидата («По шаблону»): материалы по этапу кандидата — первыми с
  пометкой, отдельная кнопка «Открыть библиотеку», сохранение документа —
  через подтверждение. Открытие библиотеки не меняет карточку и ничего не
  отправляет кандидату.
- Миграция `0018`: `category` (CHECK по закрытому словарю), `summary`,
  `seed_key` (частичный уникальный индекс) у `document_templates`; обратима;
  версионирование, immutable snapshots, аудит, optimistic locking,
  backup/update не тронуты (существующие тесты Phase 16 проходят без правок
  контрактов).
- Документация для владельца: `docs/library.md` (замена seed на свои DOCX без
  кода, форматы, дубли, хранение, безопасность).

## Честно отмеченные недоступные проверки

- **PostgreSQL-интеграционные тесты в этой среде не запускались**: песочница не
  имеет доступа к репозиториям пакетов (нет `postgresql`), `TEST_DATABASE_URL`
  недоступен. Тесты написаны (`tests/test_integration_library.py`: seed-
  идемпотентность под конкурентным запуском на частичном уникальном индексе,
  CHECK категории, видимость для обычного HR, триггеры неизменяемости) и
  выполняются в CI-джобе «Backend integration tests (PostgreSQL)». Локально
  118 интеграционных тестов корректно пропущены.
- **Ручная Windows-приёмка не выполнялась** (нет Windows в среде). Ниже —
  чек-лист для владельца на acceptance SHA.
- **Исходные DOCX владельца** приложены в репозиторий (`PROMPTS/shablony`)
  и были прочитаны для понимания структуры материалов. Встроенный seed — это
  **новые обезличенные тексты «по мотивам»**: без названий компании, города,
  актуальных цифр (МРОТ и т.п.) и персональных данных. Форматы владельца
  (DOCX) тестируются существующим пайплайном импорта; сами файлы в Git не
  копировались и в seed не включались.

## Чек-лист ручной Windows-проверки

1. Чистая роль HR видит «Шаблоны и материалы» в меню и открывает библиотеку
   одним кликом.
2. Категории понятны без документации; поиск по «собеседование» находит
   вопросник.
3. Открыть, пролистать и распечатать «Анкету кандидата для печати»
   (печатается только документ).
4. Скачать копию (HTML/TXT) — файл приходит из приложения, локальный путь не
   нужен.
5. В карточке кандидата → «По шаблону»: материал по этапу первым; «Открыть
   библиотеку» работает; сохранение документа требует подтверждения.
6. Роль без `document_lists_manage`: нет входа в «Управление материалами»,
   API отвечает 403 на создание/импорт.
7. Перезапуск программы — каталог на месте; свои правки seed не затирает.
8. Узкое окно, масштаб 100/125/150%, keyboard-only, состояние ошибки сети.

## Решения и отложенные задачи

- **Встроено как seed**: 10 обезличенных материалов (см. `docs/library.md`).
  Свои утверждённые документы владелец загружает через «Управление
  материалами» → «Загрузить из файла» и публикует; seed его выбор не
  перезаписывает.
- **Реально поддержанные форматы импорта**: .txt, .md, .markdown, .csv, .docx
  (текст документа; лимит 512 КБ / 20000 символов). PDF — отказ с понятным
  объяснением (как и в Phase 16).
- **Отложено в отдельные задачи**: серверная конвертация в PDF/DOCX;
  хранение оригинальных файлов (binary storage с антивирусом, лимитами,
  ретеншеном) — не требуется для библиотеки и меняет модель данных; персональные
  избранное/поделиться; редактирование категории/назначения у существующего
  материала после создания (сейчас задаётся при создании/импорте).
- **Хранение и retention**: только текст версий в БД (существующая модель
  версий и снапшотов), оригинальные файлы не хранятся, PII в библиотеке нет —
  отдельное решение о бессрочном хранении PII не принималось.
