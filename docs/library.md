# Библиотека HR («Шаблоны и материалы»)

Раздел «Шаблоны и материалы» в основном меню — это библиотека готовых
материалов для ежедневной работы HR: вопросники, чек-листы, скрипты звонков,
анкеты, планы онбординга и памятки. Раздел читается как книжка: открыть,
прочитать, распечатать, скачать копию. Создание и правка контента — отдельный
режим «Управление материалами», доступный только администратору или сотруднику
с правом `document_lists_manage` (сервер перепроверяет право на каждый вызов).

## Как пользоваться библиотеке

1. Откройте «Шаблоны и материалы» в левом меню.
2. Найдите материал поиском (например, по слову «собеседование») или фильтром
   по категории: Собеседование, Документы кандидата, Звонки и сообщения,
   Онбординг, Памятки HR, Вопросники по должностям.
3. Нажмите «Открыть» — материал показывается в удобном виде для чтения.
4. Действия на экране просмотра:
   - **Распечатать** — печатается только сам документ, без интерфейса программы;
   - **Скачать копию** — файл HTML (открывается в браузере, печатается в PDF)
     или **Текст (.txt)**;
   - **В новом окне** — тот же материал отдельной страницей приложения.

Старая ссылка `#/templates` открывает этот же раздел — закладки продолжают
работать.

## Встроенный стартовый каталог

На чистой установке библиотека не пустая: при первом запуске программа создаёт
десять обезличенных материалов общего назначения (без названий компаний,
городов, телефонов и других реальных данных):

| Материал | Категория |
| --- | --- |
| Чек-лист первичного телефонного разговора | Звонки и сообщения |
| Вопросник общего собеседования | Собеседование |
| Чек-лист документов кандидата | Документы кандидата |
| Анкета кандидата для печати | Документы кандидата |
| Скрипт приглашения на собеседование | Звонки и сообщения |
| Скрипт отказа и переноса встречи | Звонки и сообщения |
| План онбординга нового сотрудника | Онбординг |
| План первых 30 дней HR | Онбординг |
| Памятка HR по этапам подбора | Памятки HR |
| Вопросник: производственные должности | Вопросники по должностям |

Каталог создаётся один раз и **никогда не восстанавливается поверх ваших
правок**: если вы переименовали, изменили или отправили в архив встроенный
материал, программа считает ваш вариант окончательным.

## Как заменить встроенные материалы своими утверждёнными документами

Код менять не нужно. Порядок такой:

1. Откройте «Шаблоны и материалы» → «Управление материалами»
   (видна администратору или сотруднику с правом `document_lists_manage`).
2. **Загрузить из файла** → выберите свой DOCX или текстовый файл →
   заполните тип, категорию, название и «назначение» (одна строка для
   карточки) → «Загрузить как черновик».
3. Программа покажет текст черновика на проверку. Если всё верно —
   **Опубликовать**. Опубликованная версия сразу появляется в библиотеке у
   всех сотрудников.
4. Чтобы встроенный материал не мешался, отправьте его версию в архив
   («Версии и статусы» → «В архив») — и опубликуйте свою редакцию под тем же
   или другим названием.

Поддержанные форматы импорта: **.txt, .md, .markdown, .csv, .docx** до 512 КБ
(кодировка UTF-8; для DOCX читается только текст документа). **PDF не
читается** специально: PDF описывает страницу, а не текст, поэтому надёжного
способа вытащить текст без «кракозябр» нет — пересохраните документ в Word
как .docx и загрузите снова.

## Повторный импорт и дубли

Если загрузить файл с тем же типом и тем же названием, что у существующего
материала, программа **не создаёт молчаливую копию**, а спрашивает:

- **Новая версия существующего** — текст добавляется черновой версией к
  существующему материалу (прежние версии остаются в истории);
- **Отдельный материал** — создаётся самостоятельный материал;
- **Отмена**.

Версии неизменяемы: правка текста — всегда новая версия, у материала ровно
одна опубликованная версия, публикация новой автоматически уводит предыдущую
в архив.

## Подстановки данных кандидата

Материалы библиотеки читаются без карточки кандидата. Если в тексте
используются подстановки (например, `{{ candidate.full_name }}`), экран
просмотра показывает материал с обезличенными примерами значений и
человеческим пояснением («ФИО кандидата подставится из карточки кандидата»).
Настоящие данные подставляются только при создании документа в карточке
кандидата — то действие отдельно и подтверждается, автоматической отправки
кандидату нет.

## Хранение, безопасность, аудит

- В базе хранится **только текст** материалов и их версий; исходные файлы
  DOCX/PDF нигде не сохраняются. Удалять «файлы библиотеки» на диске не нужно
  — их нет.
- Скачивание и открытие в новом окне идут через авторизованные endpoint'ы
  приложения с `Content-Disposition`, `Cache-Control: no-store`,
  `X-Content-Type-Options: nosniff` и запрещающим скрипты CSP. Никаких
  локальных путей и `file://` не используется.
- В журнал аудита попадают только идентификаторы, версия, категория и формат —
  текст материалов и персональные данные в аудит не пишутся.
- Удаление материалов не предусмотрено (как и раньше): неактуальный текст
  уходит в архив версий.

## Технические заметки

- Миграция `0018_template_library`: колонки `category`, `summary`, `seed_key`
  у `document_templates` + CHECK по категории + частичный уникальный индекс по
  `seed_key`. Обратима; существующие данные не трогает.
- Seed выполняется при старте приложения (после создания администратора),
  идемпотентен по `seed_key` и требует хотя бы одного пользователя как автора
  версий — на production-установке без администратора он просто повторится при
  следующем старте.
- API: `GET /api/library/materials`, `GET /api/library/materials/{id}`,
  `GET /api/library/materials/{id}/download?format=html|txt`,
  `GET /api/library/materials/{id}/view`; импорт —
  `POST /api/document-templates/import` (409 при дубле) и
  `POST /api/document-templates/{id}/import-version`.
