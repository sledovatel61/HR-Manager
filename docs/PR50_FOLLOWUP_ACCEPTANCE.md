## Что исправлено

### Kanban

- Сверка с `design/mockups/bento-arctic.html`: фиксированные колонки **296 px**, промежуток **16 px**, внутренний отступ колонки 16 px, карточки 12 px. Это не растягиваемые `flex: 1` колонки.
- Обе оси прокручивает сама доска с ограниченной высотой. Вложенная вертикальная прокрутка списков внутри каждой колонки убрана. Нативная горизонтальная полоса и кнопки «Влево / Вправо» доступны без захвата карточки; доска получает клавиатурный фокус.
- Постоянный select переноса свёрнут в нативный `<details>` «Перенести». Доступный подписанный select остался. DnD, авторизация PATCH, busy/rollback и автопрокрутка у края сохранены.
- Проверены предки `.workspace`, `.workspace-main`, `.workspace-content`, сама доска. На телефоне устранено расширение страницы верхней панелью; имя пользователя и выход не выталкивают интерфейс за viewport.

### Анкеты и файлы

Подтверждённый владельцем контракт: **хранение DOCX/PDF, без распознавания, разбора анкеты и автозаполнения кандидата**.

- В шапке карточки есть «Загрузить анкету», открывающая вкладку «Документы и анкеты». Восемь вкладок переносятся на строки и не обрезаются справа.
- `DocumentsTab` остаётся чек-листом, `AttachmentsTab` — хранилищем файлов, `GeneratedDocumentsTab` — документами по шаблону. Эти сценарии не объединены.
- Загрузка: прогресс с доступной подписью, синхронная защита от повторного запроса, блокировка обоих входов загрузки при busy/квоте/отсутствии прав, сообщение об ошибке и возможность повторного выбора того же файла. Серверная защита от дубля имени не отменена: повтор после ошибки допустим, повтор успешно сохранённого имени получает честный конфликт.
- После загрузки/удаления вызывается обновление родительского списка. Рядом с именем кандидата показаны значок файла и количество вложений; нулевой индикатор не рисуется.
- Существующие скачивание, «Сохранить как…» и «Открыть сохранённый файл» после успешного сохранения через File System Access API сохранены. Отмена сохранения не считается успехом. В неподдерживаемом браузере интерфейс объясняет использование загрузок; программа не обещает сама запускать Word/Acrobat и не притворяется, что знает произвольный путь на компьютере пользователя.

### Минимальное изменение API

`GET /candidates` → `items[].attachment_count: integer`, по умолчанию 0. Это **добавочное поле только списка**, не изменение схемы БД. Для каждого авторизованного результата страницы выполняется один агрегирующий запрос к метаданным вложений. Байты/имена файлов не загружаются, N+1 запросов нет. Удалённые вложения не считаются, у удалённых кандидатов счётчик 0. Пагинация и фильтры выполняются до агрегирования.

Frontend допускает отсутствие поля для совместимости с ответом детали/старым сервером. Права API файлов и кандидатов, CSRF, owner scope, роли admin/manager/HR и аудит не изменены. Новых endpoints и миграций нет. Тексты анкет/PII в логирование не добавлены.

### Уведомления

- Строки списка — полноширинные кнопки со сброшенными браузерными фоном, рамкой и шрифтом. Заголовок, время и текст не сливаются; подвал занимает ширину поповера. На узком экране поповер привязан к верхней панели, а не выезжает за левую границу.
- «Прочитать все»: реальный `POST /notifications/mark-all-read`, затем повторный GET списка и счётчика. При подтверждённом ответе unread-состояние обновляется, бейдж показывает 0. Во время POST кнопка disabled; повторная отправка защищена ref, старый poll не перезаписывает новый результат.
- Ошибка POST не очищает бейдж. Ошибка GET после успешного POST сообщается отдельно с «Обновить», без выдуманного успешного состояния.
- Проверены фокус при открытии, Tab/Shift+Tab, Escape с возвратом на колокольчик и закрытие снаружи.

### Dark theme и график выхода

- Legacy surfaces в `styles.css`, first-run, readiness, updates, notification statuses переведены на semantic tokens. Native `option`/`optgroup`, date/checkbox controls используют явный `color-scheme` темы.
- Коллизия legacy `.detail-row` с карточкой кандидата устранена переименованием в `.candidate-detail-row`; светлые полосы не маскируются поверхностным override.
- Ячейка `.schedule-name` остаётся **table-cell**, а не flex: её высота и нижняя граница совпадают с соседними ячейками. Узкие фильтры переносятся, широкая таблица прокручивается внутри карточки дня.
- Обнаружена дополнительная причина горизонтального overflow: абсолютно позиционированный `sr-only` заголовок таблицы выходил за её scroll-контейнер. Контейнеры таблиц получили локальный positioning context; доступные подписи не удалены.
- Hardcoded screen-colors остались в определениях тематических/декоративных токенов с dark-ветками. Print-палитра намеренно отдельная. Backend/email HTML и прототипы не редактировались. Контрастный гейт и его доказательства **не ослаблялись**.

## Ограничения — что НЕ объявляется проверенным

- Это не проверка production/PostgreSQL 16, Windows desktop, Firefox/Safari или реальных данных организации. 146 integration-тестов не запускались.
- Нативный системный диалог «Сохранить как…», выдача файлового handle и запуск внешнего Word/Acrobat не проверялись end-to-end в headless Linux. Их доступные/недоступные/отменённые ветки покрыты существующими unit-тестами API/UI; ограничения явно показаны в интерфейсе.
- В fixture чек-лист кандидата ещё не применён: снимок показывает реальное пустое состояние и выбор опубликованного списка, не выдуманный заполненный checklist.

- Локальные результаты выше не означают зелёный удалённый CI или завершённую пользовательскую приёмку. PR #50 не merged, follow-up не merged.

## Воспроизведение browser acceptance

Из корня репозитория, с установленными backend dev requirements и `npm ci` в frontend. Инструменты браузера устанавливаются **вне зависимостей приложения**:

```sh
npm install --prefix /tmp/hrm-browser --no-package-lock playwright-core@1.63.0 @sparticuz/chromium@153.0.0

# Отдельный процесс: только временная in-memory test-БД, без production credentials.
PYTHONPATH=backend:scripts/acceptance .venv/bin/uvicorn pr50_fixture:app \
  --host 0.0.0.0 --port 8000 --no-access-log

# Другой процесс: Vite использует относительный /api и proxy на backend.
npm --prefix frontend run dev -- --host 0.0.0.0

# Из корня, против СВЕЖЕГО fixture-процесса (read-all изменяет тестовую БД).
HR_BROWSER_TOOLS=/tmp/hrm-browser/node_modules node scripts/acceptance/pr50_smoke.mjs
HR_BROWSER_TOOLS=/tmp/hrm-browser/node_modules node scripts/acceptance/pr50_interactions.mjs
```

`HR_ACCEPTANCE_URL` позволяет указать адрес отдельного тестового frontend. Не направлять harness в production. Fixture создаёт минимальные DOCX/PDF в `/tmp/hrm-acceptance` (`HR_ACCEPTANCE_ARTIFACTS` может изменить путь); не сохраняет БД в репозиторий. Скрипт браузера извлекает bundled NSS/NSPR libraries для изолированного Chromium. PNG сохраняются в `screenshots/pr50-follow-up/`, а не в пользовательскую папку references. Для повторного полного прогона перезапустить fixture: это сбросит только его тестовую память.
