# Решение: какой контейнерный runtime использует пилот (Docker Desktop или другой)

Вопрос задания: *нужен ли для пилота Docker Desktop, или возможен другой легальный runtime; менять runtime только с техническим и юридическим обоснованием.*

**Краткий ответ:** для пилота 0.15.0 остаётся **Docker Desktop** (официальный установщик, WSL2-бэкенд).
Альтернативы рассмотрены, юридически допустимы, но технически дороже и рискованнее **для пилота в живой эксплуатации**.
Смена runtime — отдельная задача с собственными приёмочными тестами; условия перехода описаны в конце документа.

---

## 1. Что требует задача (ограничения, из которых выбираем)

1. Windows 10/11 x64, пользователь — не программист: один `Setup.exe`, клики мышью.
2. Никаких сторонних бинарников: только официальные установщики; UAC, политики Windows и лицензии не обходятся.
3. Уже есть рабочий `infra/compose.pilot.yml` (Compose Specification v2): `env_file`-эквивалент (переменные через `pilot.env`), `${VAR:?}`-проверки, healthcheck, `depends_on`, тома `pilot_pgdata`/`pilot_backups`, сборка образов из локального снимка.
4. Baseline требований: автозапуск после перезагрузки, автоперезапуск, `127.0.0.1` по умолчанию, LAN только по явному включению, offline-лицензия.
5. Пилот работает в реальной эксплуатации → миграция стека не должна ломать данные и не должна требовать от пользователя знаний.

## 2. Сравнение вариантов

| Вариант | Лицензия/право | `docker compose` | Автозапуск/сервис | Цена внедрения у нас | Итог |
| --- | --- | --- | --- | --- | --- |
| **Docker Desktop** (текущий) | Proprietary (Docker Subscription Service Agreement). Бесплатно: личное использование, образование, некоммерческие open-source, **и малый бизнес — меньше 250 сотрудников И годовая выручка меньше 10 млн $**. В остальных случаях нужна платная подписка (Pro/Team/Business) | Полный Compose v2 в комплекте (`docker compose`) | Сам поднимает движок, автозапуск при входе, GUI «Engine running» | Уже реализовано и покрыто тестами (Docker.psm1, Compose.psm1) | **Выбран для 0.15.0** |
| **Docker Engine в WSL2 без Docker Desktop** | Свободная (Moby, Apache-2.0) | Плагин `docker-compose-plugin` ставится отдельно внутри дистрибутива | Наш supervisor должен управлять `wsl`-дистрибутивом и `dockerd` (нет штатного GUI/сервиса) | Высокая: свои health/ожидание/обновление, порт-проксирование для LAN (`netsh portproxy`) и его безопасность | Возможен, но не для пилота |
| **Podman Desktop / `podman machine`** | Свободная (Apache-2.0) | `podman compose` требует внешнего compose-провайдера (`docker-compose`/`podman-compose`); часть возможностей Compose v2 расходится | Своя машина WSL2, свой автозапуск | Средне-высокая: перепроверка всего compose-контура и миграция томов (`podman volume`) | Не для пилота сейчас |
| **Rancher Desktop** | Свободная (Apache-2.0), может работать в режиме `dockerd` (moby) | Даёт `docker` CLI и compose-плагин | Свой автозапуск, свой GUI | Средняя: это тот же Docker-CLI-контур, но другой дистрибутив/поддержка; нужно новое E2E на Windows | Кандидат №1 на замену, если появится требование уйти от лицензии Docker Desktop |
| **Удалённый Docker-хост (Linux)** | Свободная | Да | — | Противоречит «локальному» пилоту и требованию «по умолчанию только 127.0.0.1» | Отклонён |

## 3. Почему остаётся Docker Desktop

* **Технически:** `docker compose` v2 идёт в комплекте, движок сам поднимается при входе, есть GUI — Перепечай видит «Engine running» и не нуждается в терминале. Наш supervisor лишь следит за состоянием и запускает существующий compose-проект, ничего не оркеструя вручную.
* **Безопасность/политики:** мы не обходим UAC (установка идёт через `Start-HrmElevatedAndWait`, пользователь подтверждает), не отключаем Defender/Firewall, не передаём `--accept-license` за пользователя (лицензию принимает человек в окне установщика) и не скачиваем ничего, кроме официального `https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe` (проверяется Authenticode + Subject).
* **Юридически:** для небольшой компании (пилот по найму/HR) применима бесплатная категория «small business» (< 250 сотрудников и < 10 млн $ выручки). Это ограничение **честно написано** в `docs/MARIA_GUIDE.md` и в мастере: если организация не попадает в бесплатную категорию, владелец должен оформить подписку Docker. Мы не предлагаем «обход лицензии» и не советуем использовать Docker Desktop в обход условий.
* **Эксплуатация:** уже пройдены (в песочнице — автотестами, на Windows — CI-джобом `windows-installer`) сценарии: Docker отсутствует/запущен, движок не готов, стек уже запущен/сломан, порт занят, повторный запуск, обновление с откатом. Смена runtime обнулила бы эту проверку.

## 4. Когда решение пересматривается

Смена runtime инициируется владельцем, если:
1. организация попадает под платную лицензию Docker Desktop и платить за неё не планируется;
2. политика ИТ запрещает Docker Desktop как продукт.

Тогда порядок:
1. выбор: **Rancher Desktop (dockerd-режим)** — приоритет, потому что он сохраняет Docker CLI/Compose-совместимость; либо **Docker Engine в WSL2** (максимально свободный, но требует собственного управления службой);
2. техническая проверка: те же автотесты против нового runtime + отдельный набор parity-тестов compose-файла (профили, healthcheck, тома, миграции, backup-контейнер);
3. E2E на чистой Windows + обновление этого документа и `docs/MARIA_GUIDE.md`;
4. миграция данных: тома `pilot_pgdata`/`pilot_backups` переносятся дампом/копией без потери данных; обычное обновление поверх это не затрагивает.

## 5. Что делать нельзя (зафиксировано)

* скачивать Docker Desktop или compose из сторонних источников, «репаков», торрентов;
* запускать `--accept-license` от имени пользователя, отключать UAC-запросы, править политики;
* отключать Defender, брандмауэр или добавлять исключения «для скорости»;
* использовать «portable Docker» и подобные неофициальные сборки.
