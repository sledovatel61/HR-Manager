# Восстановление HR Manager (пилот 0.15.0)

Простая инструкция: что делать по порядку, если что-то не работает. Для сложных случаев в конце есть ссылка на
полный ops-runbook `docs/runbook-pilot-release.md` и `docs/backup-and-restore.md`.

**Золотое правило: ничего не удалять.** Ни программу, ни папки, ни Docker-тома. В 95% случаев достаточно перезапуска.
Данные (кандидаты, пользователи, настройки, лицензия) лежат в томе PostgreSQL и **не пропадают** от перезапусков и обновлений.

---

## 0. Первый шаг всегда одинаковый

1. Значок **HR Manager** у часов → **Проверить состояние**. В окне простыми словами написано, что не работает.
2. Там же кнопки: **Повторить**, **Открыть приложение**, **Создать отчёт для поддержки**.
3. Если не помогло — **Создать отчёт для поддержки**, файл появится на рабочем столе → отправить владельцу.

Всё остальное ниже — про конкретные ситуации.

---

## 1. Программа не открывается, в окне состояния «служба контейнеров не работает»

1. Меню «Пуск» → **Docker Desktop** → дождитесь «Engine running» (иконка-кит у часов).
2. Значок HR Manager → **Повторить** (в окне состояния).
3. Если Docker Desktop не запускается: перезагрузите компьютер, после входа в систему подождите 1–2 минуты
   (программа и Docker стартуют сами) → откройте **HR Manager**.
4. Если Docker Desktop просит вход в учётную запись Docker — вход **не обязателен** для работы пилота; закройте запрос.
5. Если написано, что нужна перезагрузка после установки Docker — перезагрузите и запустите `Setup.exe` ещё раз.

## 2. Программа открывается, но пишет об ошибке / «Приложение почти готово» висит

1. Трей → **Перезапустить приложение** (данные сохраняются) → подождать 30–60 секунд → **Открыть HR Manager**.
2. Если не помогло — трей → **Остановить приложение**, затем **Открыть HR Manager** (программа поднимется заново).
3. Не помогло — отчёт для поддержки владельцу.

## 3. Баннер про лицензию

| Что видно | Что делать |
| --- | --- |
| «Срок действия лицензии закончился» | Написать владельцу: нужен новый `*.hrmlicense`. Данные не удаляются, вход остаётся доступен. |
| «Лицензия не загружена» | Владелец присылает файл `*.hrmlicense` → раздел **Лицензия** → **Загрузить лицензию**. |
| «Файл повреждён / это не файл лицензии» | Попросить владельца прислать файл заново (файл мог испортиться при пересылке). |
| «Это файл секретного ключа» | **Никому не отправляйте этот файл.** Скажите владельцу, что случайно выбрали `private_key.hex` вместо лицензии. |
| «Подпись не совпадает с ключом установки» | Лицензия выпущена другим ключом. Владелец должен выпустить лицензию тем же ключом, что встроен в вашу версию. |

Лицензия и её ключ хранятся в базе и в каталоге состояния — перезагрузка и обновление их не сбрасывают.

## 4. Владелец потерял приватный ключ (private_key.hex)

Это **не** проблема Перепечай — приложение продолжает работать на уже выпущенной лицензии.
Последствия и порядок действий владельца:

1. Уже выпущенная лицензия действует до срока `expires_at` — продлить её без приватного ключа **нельзя**.
2. Восстановить ключ из вашей резервной копии (зашифрованная флешка/VeraCrypt/BitLocker). Поэтому резервная копия обязательна.
3. Если копии нет: создать **новую пару** (`tools/license-issuer` → «Создать ключи»), выпустить лицензии новым ключом
   и **пересобрать пилотную сборку с новым публичным ключом** (`infra/license/public_key.b64` + новый `Setup.exe`).
   Перепечай ставит новый `Setup.exe` поверх (данные сохраняются), после чего загружает новую лицензию.
4. Публичный ключ — не секрет, его можно передавать по обычным каналам. Приватный ключ — только у владельца,
   никогда в git/установщике/логах/отчёте.

## 5. Восстановление базы данных из резервной копии

Нужно только если база повреждена или данные испорчены (обычно диагностирует владелец/разработчик).

* Бэкапы создаются автоматически: перед каждым обновлением и по расписанию; лежат в томе
  `hr-manager-pilot_pilot_backups` (шифрованные, ключ — в каталоге состояния `%LOCALAPPDATA%\HRManager`).
* Порядок восстановления (полностью) — `docs/backup-and-restore.md`, раздел про restore; кратко:
  1. остановить приложение (трей → **Остановить приложение**),
  2. восстановить дамп из нужного бэкапа (владелец/разработчик по runbook),
  3. запустить приложение (трей → **Открыть HR Manager**), проверить кандидатов и лицензию.
* **Не запускайте восстановление на работающем приложении** и не удаляйте том данных — иначе бэкап не поможет.

## 6. Перестановка программы «с нуля» (крайний случай)

Обычная переустановка `Setup.exe` поверх текущей — безопасна и сохраняет данные.
Полное удаление данных требует **специального подтверждения**: команда `uninstall` принимает только явное
`-PurgeData` + фразу `УДАЛИТЬ ДАННЫЕ HR MANAGER` и предварительно делает свежий бэкап. Без этого удаление
программы **не удаляет** ни базу, ни лицензию, ни настройки.

## 7. Что отправить владельцу, если ничего не помогло

1. `HR-Manager-report-<дата>.zip` с рабочего стола (трей → **Создать отчёт для поддержки**).
2. Короткое описание: что нажимали, что видели на экране, было ли обновление перед этим.
3. Файл из каталога состояния `%LOCALAPPDATA%\HRManager\update-result.json` — если проблема появилась после обновления
   (в отчёте он тоже есть).

В отчёте нет паролей, ключей и данных кандидатов — его можно отправлять по обычной почте.
