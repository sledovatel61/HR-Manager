# HR Manager — локальный пилот на Windows (фаза 12)

Русская инструкция: установка, первый вход, обновление, удаление, диагностика.
Пилот — это ОДИН рабочий контур на ОДНОМ компьютере отдела (локальные данные,
без внешнего доступа). Права участников пилота едины: выбор «HR / Руководитель /
Администратор» при установке влияет только на порядок разделов и подсказки
интерфейса, а не на ограничения доступа.

## Установка

1. Скачайте `HRManager-Setup-<версия>.exe` из официального релиза GitHub
   (артефакт CI `hr-manager-windows-pilot`). Не берите установщик из сторонних
   мест: приложение сверяет контрольные суммы комплекта.
2. Запустите двойным щелчком — администратор не требуется. Установщик спросит
   только фамилию и рабочий режим. Пароли не спрашиваются: их генерирует сам
   компьютер и хранит в защищённой папке вашего пользователя.
3. Если Docker Desktop отсутствует, установщик предложит официальный
   установщик Docker (лицензию принимаете только вы). После установки и, при
   необходимости, перезагрузки продолжение запускается само.
4. В конце установщик откроет в браузере страницу `http://127.0.0.1:8081/first-run`
   с одноразовым кодом подтверждения (живёт 15 минут).

Ничего из настроек (часы работы, тихие часы, Telegram/e-mail) вводить при
установке не нужно — это делается позже в приложении и полностью пропускаемо.

## Первый вход

1. Введите код с экрана установщика. Учётную запись создаст сервер: имя
   пользователя придумывается автоматически из фамилии (например,
   `ivanov-pilot-a1f3`). Сам код и временный пароль вы больше нигде не увидите.
2. Задайте СВОЙ постоянный пароль (не короче 12 символов, буквы и цифры).
   Смена пароля доступна только на этом экране и только один раз.
3. Подтвердите готовность: страница покажет состояние приложения, базы,
   фоновых задач и резервных копий, затем откроет рабочее место.
4. Дальше — обычная работа HR Manager (этапы 0–11 продукта).

Повторный запуск Setup.exe НЕ создаёт второго «главного»: система отказывает
в новом первом входе, если владелец уже есть.

## Обновление

Запустите новый Setup.exe из официального релиза. Порядок строгий: блокировка
→ проверка комплекта по контрольным суммам → свежая резервная копия ДО
изменения структуры базы → установка файлов → миграции базы (только вперёд)
→ запуск новой версии → проверка готовности. Если новая версия не прошла
проверку, код и контейнеры возвращаются на предыдущую версию; база при этом
НЕ откатывается. Все попытки обновлений видны в `update-history.json`
(каталог состояния), а прогресс — в окне установщика.

## Ярлыки

После установки на рабочем столе и в «Пуск» появляются «HR Manager»
(запуск/открытие приложения) и «Диагностика HR Manager». Контейнер-служба не
показывает чёрных окон: всё работает скрыто.

## Диагностика

«Диагностика HR Manager» собирает отчёт: версии, состояние контейнеров,
краткие строки логов. Отчёт НИКОГДА не содержит пароли, ключи, токены,
сессионные cookie, адреса e-mail/телефоны и персональные данные кандидатов.
Файл лежит в `%LOCALAPPDATA%\HR Manager\state\logs\` — его можно переслать
разработчику.

## Удаление

«Приложения и возможности → HR Manager (локальный пилот) → Удалить».
По умолчанию удаляются ярлыки и контейнеры, а ДАННЫЕ сохраняются в
`%LOCALAPPDATA%\HR Manager` (база в томах Docker, зашифрованные копии,
пароли). Повторная установка продолжит работу с ними.

Полное удаление возможно только если вы лично введёте фразу
`УДАЛИТЬ ДАННЫЕ HR MANAGER`. Перед удалением установщик сохранит последнюю
резервную копию в `%LOCALAPPDATA%\HR Manager\final-backup`.

## Где что лежит

- приложение: `%LOCALAPPDATA%\HR Manager\app`
- состояние/секреты/журналы: `%LOCALAPPDATA%\HR Manager\state` (доступ — только
  вашему пользователю Windows)
- резервные копии: `state\backup` (зашифрованы; ключи рядом, доступ тот же)

## Ограничения пилота (честно)

- Один компьютер, один пилот, сетевой доступ только с этого же компьютера
  (петля 127.0.0.1). Это не серверное развёртывание.
- HTTPS не используется осознанно: веб-интерфейс доступен только локально;
  cookie-сессия живёт в этом браузере.
- Telegram и e-mail — необязательны и по умолчанию выключены.
- Автоматического обновления по сети нет: обновление — запуск нового
  Setup.exe.
- Приёмочный прогон на живой машине (`infra/windows/acceptance/`) не входит в
  GitHub Actions: CI-раннеры не выполняют Docker Desktop; прогон выполняет
  оператор пилота.
