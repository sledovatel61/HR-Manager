# HR Manager — интерактивный дизайн-прототип

Изолированный кликабельный UX/UI-прототип для этапа дизайна HR Manager.
**Это не production-код.** Он не подключается к backend, не читает и не
пишет реальные данные, использует только синтетические моковые данные (см.
`src/data/mockData.ts`).

Полное описание исследования, концепций, дизайн-системы и accessibility —
в каталоге [`../design/`](../design).

## Запуск

```bash
cd design-prototype
npm install
npm run dev       # http://localhost:4173 (или порт, который выведет Vite)
```

Продакшен-сборка и предпросмотр:

```bash
npm run build
npm run preview   # http://localhost:4173
```

Проверки:

```bash
npm run typecheck   # tsc -b
npm run lint         # eslint .
npm run build        # производственная сборка (включает typecheck)
```

## Что внутри

- **Роутинг:** минимальный hash-роутер (`src/router.tsx`), без внешних
  зависимостей.
- **Состояние:** единый React Context (`src/state/AppState.tsx`) — все
  "мутации" (смена статуса, передача кандидата, добавление события/заметки)
  живут только в памяти вкладки и сбрасываются при перезагрузке страницы.
- **Данные:** полностью синтетические, см. `src/data/mockData.ts`
  (детерминированная генерация без `Math.random`, воспроизводимо между
  запусками).
- **Дизайн-система:** токены в `src/styles/tokens.css`, компоненты в
  `src/components/ui/`.

## Демо-вход

На экране входа доступны демо-пользователи трёх ролей (HR, руководитель,
администратор) — клик по чипу подставляет имя пользователя, пароль — любой
непустой текст (реальной проверки пароля нет, это прототип).

## Ограничения

- Нет серверной пагинации/поиска — все операции происходят над локальным
  мок-массивом из ~32 кандидатов.
- Saved views визуально присутствуют, но не пересчитывают список (см.
  `design/PERSONAS_AND_FLOWS.md`, флоу 4).
- Тёмная тема реализована на общих токенах, но не прошла отдельный
  контраст-аудит (см. `design/ACCESSIBILITY.md`).
